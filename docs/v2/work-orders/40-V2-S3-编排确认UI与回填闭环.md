# 40 V2-S3 编排、确认 UI 与回填闭环

## 1. 阶段定位

- 开工条件：`V2-S2 ACCEPTED`。
- 目标：把 audio MediaHandler 接入既有会话、规则、任务 controller、closed Shadow DOM UI、DataTransfer 回填和拒收观察，形成完整但尚未最终实机放行的本地 A–H 闭环。
- 原则：最小改造 controller，复用 V1 生命周期；不要建立第二套应用。

## 2. 交付物

- media handler registry 与 controller 路由。
- 音频确认、进度、取消、成功/失败 UI。
- 音频 File 回填、恢复原文件、下载降级。
- 明确拒收后最多一次重试。
- 本地稳定页 A–H 与 Playwright/集成测试。
- UI/安全 snapshot 与诊断事件。
- 证据、追踪矩阵和 handoff。

## 3. 施工步骤

### S3.1 Controller 媒体路由

将 image 特定调用收敛到 handler：

- uploader 注册时绑定 mediaKind；
- 文件选择后再次用签名/上下文校验 handler；
- controller 调用统一 `inspect/validate/plan/process/validateOutput`；
- image 现有行为通过 adapter 保持不变；
- audio snapshot 只保留共享契约安全字段；
- 一个 session 同时只执行一个音频 pipeline；
- 新文件替换、input 移除、脚本关闭和页面卸载均 abort 当前音频任务。

不要一次性重写 1800 行 controller。优先抽取小型 media-handlers adapter，并用旧测试证明行为等价。

### S3.2 任务决策

流程必须精确为：

```text
选择文件
 -> 识别 audio uploader + 规则
 -> inspect/validate
 -> compliant: 原文件 passthrough
 -> rules insufficient / unsafe: 提示并停止
 -> plan requires confirmation
 -> 用户确认
 -> processing/progress
 -> final validate
 -> injectFile
 -> observe explicit rejection
 -> 最多一次新规则 retry
 -> success / stopped
```

页面没有 maxBytes、没有明确允许 MP3、只有时长限制、质量低于底线或官方/原始要求时，不能进入 processing。

### S3.3 确认 UI

在现有 task card 中新增 mediaKind 分支，展示：

- 原格式、原字节、格式化时长；
- 输出 MP3、目标码率、估算大小范围；
- 是否从 stereo 改为 mono；
- “有损处理，可能影响音质；不会修改原文件”；
- `开始处理` 与 `取消` 同级按钮。

要求：

- 不能只显示“优化文件”；
- mono 必须明确写出；
- 规则证据继续可查看，但不展示文件名；
- 所有外部文字以 textContent 渲染；
- 键盘、焦点、aria-live、200% 视口、reduced-motion 与 V1 一致；
- 关闭卡片不能暗中继续处理。

### S3.4 进度与取消

处理卡展示阶段：读取、解码、转换、编码、复检。百分比来自 worker，不能用计时器伪造。

- progress 必须单调且限频；
- 如果总时长未知，展示不确定进度而不是错误百分比；
- `停止处理` 立即可用；
- 取消后 UI 在 1 秒内进入已取消/原文件保留状态；
- 取消后迟到 RESULT/PROGRESS 因 taskId/abort 被丢弃；
- 用户可以重新选择文件开始新任务。

### S3.5 回填与下载降级

复用 `injectFile`：

- 成功结果必须是当前 window 的 File；
- FileList 写入后核对 name/type/size；
- 只派发既有 input/change，不伪造 trusted；
- page 未响应时使用现有 manual-submit/download fallback；
- object URL 只在下载卡可见期间存在，关闭/新任务/Dispose 时 revoke；
- 用户选择恢复原文件时走事务式 restore；
- 注入失败不得留半替换 FileList。

### S3.6 拒收与一次重试

- 只有与当前 uploader/文件时间窗口关联的明确格式/大小拒收可以形成新 candidate；
- 新规则必须比当前计划更具体，且仍允许 MP3；
- `retryCount < 1` 才可重新计划；
- 新计划如果改变码率/mono/格式事实，重新要求确认；
- 模糊失败、网络、登录、服务端、时长和语义错误停止；
- 内部两遍编码不是页面 retry，不增加 retryCount；
- 不自动点击业务上传/转写按钮。

### S3.7 本地稳定页 A–H

新增可从 `test-pages/index.html` 进入的场景：

| 场景 | 页面规则 | 预期 |
|---|---|---|
| A | MP3，max 足够 | passthrough，无新 File |
| B | MP3，max 较小 | 确认→压缩→复检→回填 |
| C | MP3 允许，源 WAV/M4A | 确认转码→回填 MP3 |
| D | 允许 MP3，无 max | rules insufficient，不处理 |
| E | max 存在，不允许 MP3 | output not allowed，不处理 |
| F | 只有时长限制 | duration unfixable，不裁剪 |
| G | processing 中取消/移除 input | 1 秒内停止、清理、无迟到注入 |
| H | 首次明确大小拒收 | 最多一次重试，第二次后停止/成功 |

页面记录事件顺序、MIME、字节、isTrusted、业务 change 和提交 click；不读取/记录音频内容或文件名。

### S3.8 诊断和清理

- 增加 PRD 音频诊断事件；
- snapshot 不包含 File/Blob/name/binary；
- session dispose 清理音频 Worker、队列、对象 URL、listener；
- 连续打开/关闭不重复 host/session；
- 图片任务执行后音频任务、音频任务后图片任务互不污染。

## 4. 自动化测试 Must

### 4.1 Controller/integration

- A–H 全流程状态和回调；
- compliant MP3 不调用 process；
- 未确认不调用 process；拒绝确认保留原 File；
- progress/迟到消息/abort/input detach；
- inject success/failure/rollback/download；
- 明确 rejection 新规则 + retryCount=1；第二次拒收停止；
- 模糊/网络/登录/时长/官方工具零处理；
- 自动提交点击恒为 0；
- 安全 snapshot 和 logger 无文件对象/名称。

### 4.2 UI/E2E

- 原/目标大小、格式、码率、mono、有损说明准确；
- 按钮同级、键盘可操作、焦点可见、aria-live；
- progress 更新不造成布局爆炸；
- cancel、close、download、restore；
- 200% 等效视口和 reduced-motion；
- 恶意规则文本只作为 textContent；
- closed Shadow DOM production 路径与测试 harness 分离。

### 4.3 回归

- V1 18 个 Vitest 文件/159 测试或当前更高数量全部通过；
- V1 图片 E2E 场景 A–F、Zent/CNIPA fixture 和安全/性能全部通过；
- production bundle 单 host、关闭后不复活、DataTransfer 行为不变。

历史数字只能作为下限参考，以执行时实际更高测试数量为准，不得为匹配 159 删除新增测试。
