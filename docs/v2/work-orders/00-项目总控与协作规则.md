# 00 V2 项目总控与协作规则

## 1. 任务目标

在 V1 图片适配已验收代码上，交付一个仍可直接粘贴进 Tabbit 的单文件 JavaScript IIFE。新增音频能力只解决：以人声为主的长录音在网页转写入口遭遇明确 MP3 格式/单文件体积墙。

V2 不重建已有 DOM、规则、AI、注入、UI 和测试框架。阶段 Agent 必须复用稳定模块，通过媒体 handler 隔离图片与音频处理。

## 2. 固定范围

### 2.1 Must

- 普通和动态单文件音频 `input[type=file]`。
- 页面明确允许 MP3且具有可信 `maxBytes`。
- MP3、M4A/AAC、WAV 输入的目标子集；最终子集由 S0 实证冻结。
- 合规文件原样放行；超限或格式不符时输出 MP3。
- 码率计算、5% 安全余量、48kbps 绝对底线。
- 有损确认、流式 Worker、进度、取消、最终复检、DataTransfer 回填。
- 明确同页拒收最多一次重试；不自动提交。
- 真实 Tabbit 单 IIFE 和实际 200MB→100MB 证据。
- V1 图片能力无回归。

### 2.2 明确不做

- 音乐质量承诺、视频抽音轨、批量、剪切、分段、降噪、增益或时长适配。
- AMR/FLAC/AIFF/WMA 等扩展格式。
- 远程编解码、第三方上传、云缓存、历史文件库。
- 无明确页面规则的主动压缩。
- 绕过可信事件、CSP、官方审核、登录或权限。

## 3. 事实来源和冲突裁决

优先级从高到低：

1. V2 PRD 安全红线和 Definition of Done。
2. V2 PRD Must/停止条件。
3. 本共享契约。
4. 当前阶段任务书。
5. V1 已验收公共契约。
6. Agent 局部实现偏好。

公共接口、依赖、许可证、内存预算、输出格式或包体超过 1.2MB 等争议必须写 `docs/decisions/ADR-NNN-标题.md`。阶段 Agent 可以提出，不得自行批准涉及产品范围或安全边界的 ADR。

## 7. 模块依赖方向

允许方向：

```text
utils/config
  -> capabilities/dom/rules/audio/image/injection/providers/ui
  -> core media-handler registry
  -> bootstrap/index
```

约束：

- `audio` 不导入 `image`，`image` 不导入 `audio`。
- 音频和图片通过同一 handler 接口交给 core，不在 controller 中散落编码器判断。
- `audio/planner` 是纯函数，不导入 DOM、UI、controller 或 Worker。
- `audio/metadata` 不产生 UI，也不调用 AI。
- `audio/worker-runtime` 不访问页面 DOM、localStorage 或网络。
- `ui` 只渲染 view model 和发出用户意图，不自行决定码率或合法性。
- 只有现有 provider 文件允许调用 Tabbit AI；音频数据永不进入 provider。
- 注入仍只有 `src/injection/file-injector.js` 可写 `input.files`。

## 9. 实现纪律

- 先写最小失败测试或能力探针，再写实现。
- 所有循环必须有次数、字节或时间上界。
- 所有 Worker、AudioData、对象 URL、事件、observer 和大缓冲有清理路径。
- 不用测试专用分支进入 production bundle。
- 不把 200MB fixture、生成音频或浏览器 profile 提交到 Git。
- 非敏感小 fixture 放 `tests/fixtures/generated/audio/`，由确定性脚本生成并记录 manifest。
- 不修改 PRD/任务书让代码通过；发现不合理要求写 ADR/阻塞报告。
- 保留用户工作区已有变更，不进行 reset/checkout 丢弃。
- 每阶段结束执行 `git diff --check`、`npm run check` 和该阶段 E2E。

## 12. 阻塞处理

立即停止的情况：

- Tabbit 真实能力与 S0 方案不一致；
- 编码器许可证或分发义务无法确认；
- 必须远程加载代码/模型/二进制；
- 200MB 处理需要完整 PCM 或主线程不可取消；
- 为满足体积必须突破 48kbps 底线；
- 上游契约缺失或需要改变安全边界；
- 需要真实敏感录音、登录发布权限或对真实业务执行提交。

阻塞报告必须写：复现、预期/实际、已排除项、证据、至少两个可选方案、推荐方案和继续施工所需的明确授权。

## 13. Git 与提交

- 每阶段使用独立、聚焦的提交；文档与代码可以同阶段提交，但不要混入无关修改。
- 提交前列出 `git status --short` 和 `git diff --stat`。
- 不推送远程、不创建 PR、不公开 Tabbit 脚本，除非用户另行授权。
- `dist/uploadfit.js` 是发布物，源码变化后按现有流程重建并记录 bytes/SHA。

## 14. 独立验收责任

施工 Agent 证明“按任务书完成并可复查”；主验收 Agent 负责用未依赖施工会话的命令和实机路径复验。自动化绿灯不能替代 Tabbit 实机、200MB 输入、外部请求为零、可取消和不自动提交。
