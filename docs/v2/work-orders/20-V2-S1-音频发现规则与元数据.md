# 20 V2-S1 音频发现、规则与元数据

## 1. 阶段定位

- 开工条件：`V2-S0 ACCEPTED`，ADR 已冻结编解码方案和输入子集。
- 目标：让系统在不处理音频的情况下，可靠识别音频上传器、页面 MP3/体积规则、源文件真实格式与元数据，并对不安全场景停止。
- 本阶段不实现正式编码、UI 确认或回填。

## 2. 交付物

- 媒体分类：扩展现有 input discovery/context，不破坏 image 行为。
- 音频 MIME/扩展名规则归一和确定性解析。
- MP3/WAV/M4A 子集签名及有界元数据读取。
- AudioMetadata、音频预检与 validation。
- 快速/完整 fixture 生成和 manifest。
- unit/integration 测试、证据和 handoff。

## 3. 施工步骤

### S1.1 媒体分类

在现有发现链路中增加 `mediaKind`，满足：

- `accept="audio/*"`、`.mp3,.m4a,.wav`、规范音频 MIME 可识别为 audio；
- 图片 token 仍识别为 image；
- 混合 image/audio、video-only、application/pdf、裸 file input 不被提前判为 audio；
- 动态新增、open shadow、关联 label/help/error 与 V1 生命周期一致；
- `multiple` audio input 只注册为不可自动处理上下文，不消费多文件；
- 用户选择受支持音频后，裸 input 只有在附近强音频证据存在时才升级；
- UploadFit 自己 UI 中的隐藏 input 不得被递归发现。

不得复制一套新的 MutationObserver；复用 V1 discovery 和 cleanup。

### S1.2 规则解析与归一

至少覆盖：

```text
仅支持 MP3
支持 mp3、m4a、wav
格式：.MP3
音频不超过 100MB
单文件最大 100 MB
大小上限 100000000 字节
最大 25MiB
时长不超过 2 小时
请上传原始录音/无损 WAV
请使用官方音频审核工具
```

要求：

- MP3 归一为 `audio/mpeg` + `.mp3`；
- 音频上下文中的 MB/MiB/字节沿用 V1 保守解析和证据溯源；
- 时长规则解析到 advisory/duration，但不生成裁剪/分段计划；
- “原始、无损、证据、官方工具”等进入 safety semantic；
- 纯页面营销文字、FAQ 其他卡片、视频限制不污染当前 uploader；
- AI 输出仍经本地证据和数字 token 验证，且 provider 输入不新增文件元数据。

### S1.3 签名识别

按 S0 冻结子集实现：

- MP3：ID3v2 跳过、MPEG audio frame sync、版本/layer/采样率/声道合法性；
- WAV：RIFF/WAVE、chunk 边界、`fmt `、`data`，拒绝越界长度和未知压缩子集；
- M4A：ISO BMFF `ftyp`/`moov`/`trak`/sample description，确认 AAC-LC；
- WebM/Opus 若 S0 未纳入，稳定返回 unsupported，不留下半实现。

扩展名、`File.type` 与签名冲突必须产生错误或 warning，不静默相信名称。

### S1.4 元数据读取

实现 `inspectAudio(file, options)` 或共享契约等价接口：

- 累计元数据读取默认 ≤1MiB；
- 对尾部索引使用有界 `slice()`；
- 解析 duration、sampleRate、channels、bitDepth/averageBitrate（适用时）；
- MP3 VBR 使用 Xing/VBRI/受控帧扫描，不能用首帧假精确；
- WAV 时长以 data chunk / byteRate 交叉验证；
- M4A 时长使用 timescale/duration 并验证有限值；
- 支持 AbortSignal；取消后停止继续读取；
- 处理截断、伪造 chunk 长度、零时长、超大数和 NaN。

如果特定 VBR 文件需要超过 1MiB 扫描，必须返回近似/unsupported 或通过 ADR 修改预算，不得无限扫描。

### S1.5 Validation

验证输出至少区分：

- 合规且格式允许/字节合规：passthrough；
- 格式允许但超限：需要音频有损处理；
- 源 M4A/WAV 不允许但 MP3 允许：需要转码；
- MP3 不允许：unfixable；
- maxBytes 缺失/冲突：rules insufficient；
- duration-only：`AUDIO_DURATION_LIMIT_UNFIXABLE`；
- 原始/无损/官方要求：安全停止；
- unsupported/corrupt：稳定音频错误码。

本阶段只产出 validation，不真正处理。

## 4. 测试矩阵

### 4.1 媒体分类 Must

- audio accept、扩展名列表、MIME 列表；
- image、video、PDF 和混合 accept 负例；
- 动态节点、open shadow、移除清理；
- 裸 input 强/弱上下文；
- V1 图片 discovery 全量回归。

### 4.2 规则 Must

- 至少 20 个音频格式/大小中文表达正例；
- 至少 15 个弱文本、其他 uploader、视频/图片和营销文案负例；
- MB/MiB/字节边界和冲突；
- MP3 允许的强证据；
- 时长/无损/官方工具停止；
- 恶意文本与 HTML 不进入 UI 注入。

### 4.3 元数据 Must

- 每个 S0 支持子集至少 2 个正 fixture；
- MP3 CBR/VBR/ID3；WAV PCM；M4A AAC-LC；
- 扩展名/MIME/签名冲突；
- 截断、伪造长度、零时长、超通道、unsupported codec；
- 读取字节预算和 abort；
- 安全 snapshot 不含 File/name/binary。

fixture 必须由脚本确定性生成或来自许可证清晰的小型资产，并在 manifest 记录来源、参数、bytes、SHA 和许可。不得提交真实录音。
