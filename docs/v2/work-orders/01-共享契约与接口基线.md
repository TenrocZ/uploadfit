# 01 V2 共享契约与接口基线

## 1. 目的

本文件冻结 V2 各阶段共享的数据结构和模块边界。S0 可根据真实编解码能力提出一次 ADR 修订；S0 被验收后，后续阶段不得自行改变字段语义、质量底线或安全行为。

> 2026-08-25 授权例外：产品所有者已把超限 MP3 重编码、AAC-LC M4A→MP3、英文规则和 transient 拒收修复纳入 `V2-S4.1`。施工 Agent 必须按 `55-V2-S4.1-MP3-M4A转码与拒收监听修复.md` 先完成真实 Tabbit Worker 门禁和 ADR-006，才可扩展内部 decoder/demux 能力；本文件既有公开字段、错误语义、安全底线和单任务约束默认不变。确需新增或改变契约时，必须在 ADR-006、迁移测试和 handoff 中逐项列出，不能静默修改。

以下代码块是接口形状，不要求逐字复制实现；公开字段和语义必须一致。

## 3. MediaKind 与上传器契约

```js
const MEDIA_KINDS = ['image', 'audio'];

UploaderContext = {
  id: string,
  input: HTMLInputElement,
  mediaKind: 'image' | 'audio',
  acceptTokens: string[],
  multiple: boolean,
  associatedText: string,
  form: HTMLFormElement | null,
  rootKind: 'document' | 'open-shadow',
  adapterId: string | null
}
```

规则：

- 每个 uploader 在注册时只有一个 `mediaKind`。
- `accept="image/*,audio/*"` 的混合控件不在音频 MVP 自动处理范围，标记 ambiguous。
- 裸 file input 只有在用户选中文件且上下文足够时才可升级分类；不能同时注册两个 handler。
- `multiple` 音频 input 可被发现但 V2 不自动处理，显示不支持提示。

## 4. RuleSet 增量

沿用 V1 RuleSet，新增或明确：

```js
RuleSet = {
  mediaKind: 'image' | 'audio' | null,
  formats: string[],       // MIME，小写规范值
  extensions: string[],    // 包含前导点，例如 .mp3
  minBytes: number | null,
  maxBytes: number | null,
  duration: {
    exactMs: number | null,
    minMs: number | null,
    maxMs: number | null
  },
  audio: {
    sampleRates: number[],
    channels: number[],
    bitDepths: number[]
  },
  confidence: number,
  sources: RuleSource[],
  conflicts: RuleConflict[],
  advisories: object[],
  safetyFlags: string[],
  actionable: boolean
}
```

V2 音频执行只消费 `formats/extensions/maxBytes`。`duration/audio` 先用于展示、停止判断和未来兼容，不能在 V2.0 中偷偷扩展成专业音频转换。

规范 MIME：

| 表达 | 规范值 |
|---|---|
| MP3、`.mp3`、`audio/mp3` | `audio/mpeg` |
| M4A、`.m4a` | `audio/mp4` |
| AAC、`.aac` | `audio/aac` |
| WAV、`.wav`、`audio/x-wav` | `audio/wav` |
| WebM、`.webm` | `audio/webm` |

页面允许 MP3 的判断必须接受 `audio/mpeg` 或 `.mp3` 的确定性证据，不接受仅出现“常见音频格式”。

## 5. AudioMetadata

```js
AudioMetadata = {
  mediaKind: 'audio',
  fileType: string | null,
  signatureMime: string | null,
  container: 'mp3' | 'mp4' | 'wav' | 'webm' | null,
  codec: 'mp3' | 'aac-lc' | 'pcm' | 'opus' | null,
  size: number,
  durationMs: number | null,
  sampleRate: number | null,
  channels: number | null,
  bitDepth: number | null,
  averageBitrate: number | null,
  variableBitrate: boolean | null,
  seekable: boolean,
  inspectedBytes: number,
  errorCode: string | null,
  warnings: Array<{ code: string }>
}
```

要求：

- `size` 来自 File 字节数，不来自页面文本。
- `signatureMime/container/codec` 来自二进制检查，不信任扩展名。
- `durationMs` 不得是通过文件大小除以单个随机帧码率得到的伪精确值。
- 安全 snapshot 不包含文件名、原始标签、二进制或用户目录。

## 6. AudioValidationResult

```js
AudioValidationResult = {
  valid: boolean,
  violations: Array<{
    code: string,
    expected: unknown,
    actual: unknown
  }>,
  warnings: Array<{ code: string }>,
  safeAutoFixes: string[],
  requiredConfirmations: Array<{
    type: 'AUDIO_LOSSY_TRANSCODE' | 'AUDIO_DOWNMIX_MONO',
    required: true
  }>,
  unfixable: string[]
}
```

`valid: true` 的合规文件必须 passthrough，不能因为“可以更小”而生成计划。

## 7. AudioProcessingPlan

```js
AudioProcessingPlan = {
  mediaKind: 'audio',
  sourceContainer: string,
  sourceCodec: string,
  targetMime: 'audio/mpeg',
  targetContainer: 'mp3',
  targetCodec: 'mp3',
  targetMaxBytes: number,
  safeTargetBytes: number,
  targetBitrateKbps: number,
  targetSampleRate: number | null,
  targetChannels: 1 | 2,
  operations: Array<
    'TRANSCODE_AUDIO' |
    'REENCODE_AUDIO' |
    'RESAMPLE_AUDIO' |
    'DOWNMIX_MONO'
  >,
  confirmations: Confirmation[],
  estimatedOutputBytes: { min: number, max: number },
  encodePassLimit: 2,
  executable: boolean,
  passthrough: boolean,
  unfixable: string[],
  warnings: Array<{ code: string }>
}
```

不变量：

- `targetMime` 只允许 `audio/mpeg`。
- `safeTargetBytes <= targetMaxBytes`。
- `targetBitrateKbps` 必须来自 PRD 离散阶梯且不低于 48。
- `encodePassLimit` 固定不超过 2；它是回填前的本地纠偏，不计入页面拒收重试。
- `DOWNMIX_MONO` 存在时必须有未解决的 `AUDIO_DOWNMIX_MONO` 确认。
- 任意音频重编码必须有 `AUDIO_LOSSY_TRANSCODE` 确认。

## 8. 确认契约

```js
Confirmation = {
  id: string,
  type: 'AUDIO_LOSSY_TRANSCODE' | 'AUDIO_DOWNMIX_MONO',
  required: true,
  resolved: boolean,
  accepted: boolean | null,
  payload: null,
  suggestedPayload: {
    fromMime?: string,
    toMime: 'audio/mpeg',
    originalBytes: number,
    safeTargetBytes: number,
    bitrateKbps: number,
    channels: number
  }
}
```

用户拒绝任一必需确认后任务停止并保留原文件。不得用一次历史确认覆盖新文件、新上限或新的单声道方案。

## 9. AudioProcessResult

```js
AudioProcessResult = {
  file: File,
  metadata: AudioMetadata,
  operations: string[],
  validation: AudioValidationResult,
  durationMs: number,
  inputBytesRead: number,
  outputBytes: number,
  workerUsed: true,
  encodePasses: 1 | 2,
  peakBufferedBytes: number | null,
  warnings: Array<{ code: string }>,
  passthrough: boolean
}
```

`file` 只存在于运行时结果，安全 snapshot/日志不得序列化文件对象。

## 10. MediaHandler 接口

推荐统一接口：

```js
MediaHandler = {
  kind: 'image' | 'audio',
  supports(file, uploaderContext): boolean,
  inspect(file, options): Promise<ImageMetadata | AudioMetadata>,
  validate(metadata, rules, options): ValidationResult,
  plan(metadata, rules, options): ProcessingPlan,
  resolveConfirmation(plan, confirmation): ProcessingPlan,
  process(file, plan, options): Promise<ProcessResult>,
  validateOutput(metadata, rules, plan): ValidationResult,
  dispose?(): void
}
```

controller 只依赖 handler 接口。图片既有函数可以由轻量 adapter 包装，不要求重写 image 模块。

## 11. Worker 消息契约

主线程到 Worker：

```js
{ type: 'START', taskId, file, plan, limits }
{ type: 'CANCEL', taskId }
{ type: 'DISPOSE', taskId }
```

Worker 到主线程：

```js
{ type: 'READY', taskId, capabilities }
{ type: 'PROGRESS', taskId, phase, processedMs, totalMs, ratio }
{ type: 'RESULT', taskId, blob, stats }
{ type: 'ERROR', taskId, errorCode }
{ type: 'CANCELLED', taskId }
{ type: 'DISPOSED', taskId, released }
```

约束：

- `taskId` 不匹配的消息必须忽略。
- ratio 必须有限并截断在 0–1。
- progress 最快 100ms 一次，避免主线程消息洪泛。
- 错误只跨线程传稳定 code，不传原始文件名或大堆栈。
- 取消/完成后 Worker 不得继续发送进度。

## 12. 状态与转移

沿用 V1 任务状态，音频至少走：

```text
ARMED
  -> INSPECTING
  -> PASSTHROUGH
  -> NEEDS_CONFIRMATION
  -> PROCESSING
  -> INJECTING
  -> SUCCESS
  -> WAITING_REJECTION
  -> RETRYING (最多一次明确新规则)
  -> STOPPED / DISPOSED
```

新增 `processingProgress` 只能作为 task snapshot 字段，不新增一套平行状态机。

必须加入共享错误白名单：

```text
AUDIO_CODEC_UNSUPPORTED
AUDIO_METADATA_INVALID
AUDIO_DECODE_FAILED
AUDIO_ENCODE_FAILED
AUDIO_TARGET_UNSAFE
AUDIO_OUTPUT_TOO_LARGE

AUDIO_MEMORY_BUDGET_EXCEEDED
```

## 15. 输出命名

输出文件名仅在运行时生成：

```text
<safe-base>-uploadfit.mp3
```

- 去除原扩展名和路径字符；空 base 使用 `audio-uploadfit.mp3`。
- 不覆盖磁盘原文件。
- 日志、AI、JSON 证据和截图不记录真实原始名称。

## 16. 最终验证契约

回填前必须同时满足：

```js
metadata.signatureMime === 'audio/mpeg'
metadata.container === 'mp3'
metadata.durationMs > 0
outputFile.size > 0
outputFile.size <= rules.maxBytes
validation.valid === true
```

建议目标 `outputFile.size <= safeTargetBytes`；若位于 `safeTargetBytes` 与 `maxBytes` 之间但仍合法，可以通过并记录 `AUDIO_SAFETY_MARGIN_MISSED` warning，不得因此编码第三次。

## 17. 安全 snapshot

controller/UI 可见的音频 snapshot 只允许：

```js
{
  mediaKind,
  mime,
  container,
  codec,
  size,
  durationMs,
  sampleRate,
  channels,
  bitrateKbps,
  progress,
  errorCode
}
```

不得包含 File/Blob、文件名、二进制、Base64、PCM、完整 tags、用户目录或原始错误堆栈。

## 18. 公共契约变更流程

1. 先新增 ADR，说明现状、真实证据、选项、推荐、迁移和回滚。
2. 同时更新本文件、PRD 追踪矩阵和受影响任务书。
3. 更新所有消费者和测试，不能保留两个含义不同的同名字段。
4. 阶段 handoff 列出变更前后形状。
5. 主验收 Agent批准前保持阶段 `BLOCKED` 或 `READY_FOR_ACCEPTANCE`，不得自行宣告新契约生效。
