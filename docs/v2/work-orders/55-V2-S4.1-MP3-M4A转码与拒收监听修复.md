- 阶段代号：`V2-S4.1`。
- 状态：`AUTHORIZED_FOR_IMPLEMENTATION`；施工 Agent 完工后只能写 `READY_FOR_ACCEPTANCE`。

本阶段是产品缺陷修复和已写入 PRD 的音频范围补齐，不再按“V2.1 未来扩展”延期。它明确解禁：

2. 常见 M4A/AAC-LC 在需要跨越格式墙或体积墙时转换为 MP3；
3. 页面通过短生命周期 toast/snackbar/notification 明确拒收时，UploadFit 能在现有 30 秒窗口内捕获、解析、展示并按既有规则最多重试一次；

本施工单覆盖此前以下冻结，但不改写历史验收事实：

## 2. 已确认缺陷与现场事实

### D1：超限 MP3 被错误归为不可处理

- Podcastools 页面规则：允许 MP3/WAV/M4A，最大 10,000,000 bytes，同时最长 10 分钟。
- UploadFit 能把测试文件正确识别为 `audio/mpeg / mp3 / codec=mp3`，元数据没有损坏错误；失败来自 planner 对超限 MP3 固定加入 `AUDIO_CODEC_UNSUPPORTED`。
- 当前 59.39 MB 测试 MP3 时长约 24:45；30.48 MB 测试 MP3 时长约 12:42，二者都超过该站 10 分钟。因此它们不能作为 Podcastools 的“压缩后应成功”正例；即使补齐重编码，也必须先因时长墙停止。
- Podcastools 正例必须另造“时长不超过 10 分钟、体积超过 10 MB”的合法 MP3，例如约 8 分钟、320kbps 的非敏感合成音频。

### D2：VocaText 明确拒收未被观察

- 页面正文声明免费版最大 25 MB，但该文字不与上传 input 直接关联；首轮规则为 `maxBytes=null`、`actionable=false`，UploadFit 正确进入等待网页反馈的路径。
- 页面脚本通过 `#toast` 显示 `File exceeds 25 MB limit.`，约 2.4 秒后隐藏。
- 当前 observer 的错误节点选择器不包含 toast/snackbar/notification；英文 classifier 也不能把 `exceeds / limit / too large` 识别为明确拒收；byte parser 不能从该英文句子形成 `maxBytes`。
- 结果是网页拒绝已经发生，但 UploadFit 等待窗口最终超时并显示 passthrough，用户没有可追溯原因。

### D3：M4A 只识别元数据，不能处理

- 当前 metadata/signature 已能识别部分 AAC-LC M4A，但 worker 只有 PCM WAV→lamejs 的编码入口，没有 M4A demux/decode。
- planner 因此对所有 M4A/AAC 固定停止，未达到 PRD 的格式墙目标。

## 3. 产品范围

### 3.1 Must

- 合规且页面允许、未超限的 MP3 继续原 File passthrough；不得为了“优化”重编码。
- 合法超限 MP3 在页面明确允许 MP3且存在可信 `maxBytes` 时形成 `REENCODE_AUDIO` 计划，经有损确认后输出 MP3。
- 合法 M4A/AAC-LC 在以下任一情况形成 `TRANSCODE_AUDIO` 计划：
  - 页面不允许 M4A 但明确允许 MP3；
  - 页面允许 M4A，但源文件超过可信 `maxBytes` 且页面明确允许 MP3 输出。
- 页面允许 M4A、文件未超限且无其他可修复违规时，原 File passthrough，不做无意义转换。
- 中文和英文的明确大小/时长规则均可确定性解析；时长超过上限时优先停止为 `AUDIO_DURATION_LIMIT_UNFIXABLE`，不得通过降低码率掩盖时长违规。
- 捕获上传器关联错误节点及单活跃任务场景下的全局 toast/snackbar/notification；明确新规则仍只允许一次 retry。
- 编解码继续在单 IIFE 内的本地 Blob Worker 中完成，无远程 runtime 依赖。
- 最终 MP3 必须经过签名、完整帧、字节、时长、采样率/声道和代表帧解码复检后才回填。

### 3.2 S4.1 冻结输入子集

施工 Agent 必须在 ADR-006 和 capability evidence 中给出最终精确子集，最低 Must 为：

| 输入 | Must 子集 | 行为 |
|---|---|---|
| MP3 | 有效 MPEG Layer III；mono/stereo；常见 32/44.1/48kHz；CBR 与带有效 Xing/VBRI 或可有界扫描的 VBR | 合规 passthrough；超限重编码 |
| M4A | ISO BMFF/M4A；AAC-LC `mp4a.40.2`；mono/stereo；32/44.1/48kHz；非加密、非 fragmented；`moov` 在 `mdat` 前或后；`stco`/`co64` | 合规且允许时 passthrough；格式不符或超限时转 MP3 |
| WAV | 既有 PCM 16/24/32-bit mono/stereo | 行为不回归 |

以下仍是明确停止项：HE-AAC、HE-AACv2、ALAC、DRM/加密 M4A、fragmented MP4/`moof`、损坏 sample table、超过资源上界的容器表、raw ADTS `.aac`（除非 ADR-006 另有真实门禁和产品方批准）、三声道及以上。

### 3.3 继续不做

- 裁剪、分段、合并、删除静音、变速或任何时长修改；
- 音乐质量保证、降噪、响度、人声增强；
- 视频抽音轨；
- 页面未明确允许 MP3或没有可信字节上限时主动压缩；
- 网站域名硬编码、VocaText 专用 adapter 或全页无限文本抓取；
- 自动点击上传、转写、提交、保存、付款或发布按钮；
- 用远程 API、CDN、本机 ffmpeg、Node 原生能力或完整输入 `decodeAudioData()` 冒充 Tabbit runtime。

## 4. D0 强制技术门禁：先解码，再改 planner

外部 Agent 不得先删除 `AUDIO_CODEC_UNSUPPORTED` 分支。必须按以下顺序施工。

### 4.1 Worker 原生解码探针

优先路线固定为：

```text
MP3/M4A File.slice()
  -> bounded demux/frame iterator
  -> Dedicated Blob Worker 内 AudioDecoder
  -> bounded AudioData/PCM queue
  -> 现有 lamejs@1.2.1 encoder
  -> MP3 chunks/Blob
  -> 独立最终验证
```

在真实 Tabbit 中分别对 `codec: 'mp3'` 与 `codec: 'mp4a.40.2'` 完成：

1. `AudioDecoder.isConfigSupported()` 只作前置记录，不能单独算 PASS；
2. 投递真实、非伪造的 encoded chunks；
3. 至少获得一个可验证 `AudioData` 输出，并核对 frames/sampleRate/channels；
4. `AudioDecoder` 必须位于 production 等价 Blob Worker；仅 MAIN world 可用不算通过；
5. flush、error、cancel、close 和再次运行均有证据；所有 `AudioData.close()` 可核查；
6. 不读取、回传或记录 PCM/Base64 到证据。

任一 Must codec 无法在 Worker 中真实解码时，对应格式状态必须为 `BLOCKED_CORE_GATE`。不得退化为主线程整文件解码，也不得静默宣称支持。

### 4.2 ADR-006

在写 production decoder/demuxer 前新建：

```text
docs/decisions/ADR-006-V2-S4.1-MP3-M4A解码方案.md
```

ADR 至少记录：

- 原生 WebCodecs、内部最小 demuxer、第三方 demux 库三个选项；
- 真实 Tabbit Worker probe；
- MP3/M4A 精确子集与拒绝子集；
- dependency/version/source/license/NOTICE/relinking；
- production bundle 增量 bytes；
- sample table、PCM queue、output Blob 的内存上界；
- 取消、错误、回滚与回退策略；
- 迁移 ADR-005 冻结边界的方式；
- 回滚方法。

优先使用原生 `AudioDecoder` + 有界内部 demux；若引入依赖，必须锁版本并完成许可证/供应链审查。不得仅因实现方便引入完整 FFmpeg/WASM 工具链。

## 5. 编解码实现契约

### 5.1 MP3 demux/decode

- 复用现有 ID3、首帧和 MPEG header 解析，不复制不一致的第二套签名规则。
- 逐片读取并恢复跨 slice 的残留帧；残留上界不得随文件增长。
- 每帧核对 version/layer/bitrate/sampleRate/channels/frameLength；畸形或截断稳定失败。
- timestamp/duration 按累计 sample count 生成，不用文件名、扩展名或首帧码率猜测全程。
- VBR 必须使用有效索引或受控完整帧迭代；不得把首帧 CBR 估算当精确时长。

### 5.2 M4A demux/decode

- 解析并交叉验证 `ftyp/moov/trak/mdia/minf/stbl/stsd/mp4a/esds/stts/stsc/stsz/stco/co64/mdat`。
- 只选择唯一、有效的 AAC-LC 音轨；多音轨或含视频不能默认猜测，除非可确定性选出唯一 audio track 且 ADR 明确。
- `esds` 中 AudioSpecificConfig 必须作为 `AudioDecoderConfig.description`；object type 必须为 AAC-LC。
- sample offset/size/duration 表必须有最大条目数、最大累计表字节和整数溢出校验；offset 必须落在文件及合法 `mdat` 范围内。
- `moov` 位于尾部时只做有界尾部/box 定位；不得先把整个 M4A 放进 ArrayBuffer。
- fragmented MP4、edit list 导致不可确定时长、异常 timescale、损坏/重叠 sample table 均稳定停止。

### 5.3 PCM 与编码背压

- decoder 输出转为现有 encoder 接受的 Int16 mono/stereo chunk；禁止完整 PCM 常驻。
- `decodeQueueSize`、待关闭 `AudioData` 数、PCM bytes 和 encoder output queue 都必须有硬上界。
- 推荐最大未释放 PCM 预算继续不超过 32MiB；若必须调整，写 ADR 和实测，不得取消上界。
- 写入 lamejs 前完成必要的 interleave/deinterleave/downmix/resample；不能因为输入是 MP3/M4A 绕过 mono 确认。
- 每个 `AudioData` 在复制完必要 plane 后立即 `close()`，异常和取消路径也必须 close。
- 输出仍最多两遍编码；第二遍必须重新创建 decoder/encoder 并证明上一遍资源已释放。

### 5.4 Worker 协议

- 扩展现有 worker implementation，不创建第二套 controller 或绕过 `audio/handler`。
- 消息必须带现有 taskId/类型校验；伪造、迟到和前一遍消息不能污染当前结果。
- progress 至少区分 `demux/decode/encode/validate`，对外可合并展示，但 ratio 必须单调、≤10 次/秒。
- cancel 后 1 秒内停止产生新 chunk/result；decoder、AudioData、Blob URL、临时数组全部清理。

## 6. Planner、验证与 UI

### 6.1 Planner 决策表

| 源文件 | 页面规则 | 预期 |
|---|---|---|
| MP3，大小合规 | 明确允许 MP3 | 原 File passthrough |
| MP3，超过 maxBytes | 明确允许 MP3 + maxBytes | `REENCODE_AUDIO` + 有损确认 |
| M4A，大小合规 | 明确允许 M4A | 原 File passthrough |
| M4A，大小合规 | 不允许 M4A、明确允许 MP3 + maxBytes | `TRANSCODE_AUDIO` + 有损确认 |
| M4A，超过 maxBytes | 明确允许 MP3 + maxBytes | `TRANSCODE_AUDIO` + 有损确认 |
| 任一支持格式，超过 duration.maxMs | 任意体积规则 | `AUDIO_DURATION_LIMIT_UNFIXABLE`，Worker=0 |
| MP3/M4A，目标需低于 48kbps | 明确 maxBytes | `AUDIO_TARGET_UNSAFE`，Worker=0 |
| M4A 非 AAC-LC/损坏/加密/分片 | 任意 | `AUDIO_CODEC_UNSUPPORTED` 或稳定 decode/metadata 错误，Worker 不编码 |

合法 MP3/M4A 不得再仅因容器为压缩格式而加入 `AUDIO_CODEC_UNSUPPORTED`。该错误仅保留给真实不支持的 codec/profile/container 或 runtime capability failure。

### 6.2 确认与错误文案

- MP3→MP3 显示“重新编码 MP3”；M4A→MP3 显示“将 M4A 转为 MP3”。
- 均展示原大小、时长、目标上限、目标码率、预计大小、是否改单声道和有损警告。
- 时长超限必须明确说明“压缩不会缩短时长，UploadFit 不裁剪/分段”，不能显示“编码不支持”。
- decoder/demuxer 失败不得显示原始异常、文件名、box/tag 内容或堆栈。
- 原文件始终保留；确认拒绝、处理失败、取消或回填失败不能把半成品留在 input。

## 7. 英文规则与 transient rejection 修复

### 7.1 确定性解析

至少支持并测试：

```text
Max 10 MB and 10 minutes.
Files up to 25 MB.
Maximum file size: 100 MB.
File must be under 20MB.
File exceeds 25 MB limit.
Audio length must not exceed 2 hours.
```

要求：

- byte qualifier 同时检查数字前后的 `max/maximum/up to/under/no more than/exceeds/too large/limit`，但只在文件/上传/音频语境生成规则；
- duration 支持 `ms/second(s)/sec/minute(s)/min/hour(s)/hr` 及中文单位；
- `Max 10 MB and 10 minutes` 同时生成 `maxBytes=10000000` 和 `duration.maxMs=600000`；
- `File exceeds 25 MB limit.` 作为 rejection candidate 生成 `maxBytes=25000000`；
- 成功提示、营销文案、价格/套餐数字、无文件语义的 toast 不生成规则；
- 不把全页 FAQ 当高可信 nearby text，不突破现有 6000 字符和去敏预算。

### 7.2 toast/snackbar/notification 观察

在 `rejection-observer` 的有界 30 秒窗口内：

- 候选节点增加 toast/snackbar/notification 的 id/class/data attribute 形态；
- 观察 `childList`、`characterData`，以及受限的 `class/hidden/aria-hidden` 可见性属性变化；
- 只保存清洗后最多 600 字符的候选文本；MutationObserver 不序列化页面；
- 明确关联上传器的节点优先；全局提示只有在恰好一个可观察任务时才可关联；多任务无法唯一归属时返回 `AMBIGUOUS_REJECTION_ASSOCIATION`；
- classifier 增加英文拒绝语义：`unsupported/not allowed/cannot upload/upload failed/invalid/exceeds/too large/maximum/limit/must/required`；
- `uploaded successfully / copied / saved / transcription complete` 等成功 toast 必须为 irrelevant；
- 识别出的 rejection 仍必须经过本地 parser、resolver、`isStrictlyMoreSpecificAudioRejection` 和最多一次 retry，不允许 toast 文本直接控制码率或调用处理器。

不得增加 `vocatext.com` 域名特例。修复必须对同类站点通用。

| R03 | 预先存在隐藏 toast，后改 text/class | 2.4 秒内捕获，不依赖新增节点 |
| R04 | `Upload complete`/`Copied`/价格 toast | irrelevant，process=0 |
| R05 | 两个活跃 uploader + 全局 toast | 不猜归属；稳定歧义错误 |
| R06 | 明确拒收后处理成功 | retryCount=1；第二次拒绝不再处理 |
| R07 | observer timeout/pagehide/dispose | observer/timer 全清理 |

### 10.2 Codec 与计划

| ID | 场景 | 必须断言 |
|---|---|---|
| C01 | 合规 MP3 | 原 File identity passthrough；decoder/encoder=0 |
| C02 | ≤10min 且 >10MB 的真实 MP3 | reencode 计划；确认后 ≤10MB；时长误差≤2%或250ms取大者 |
| C03 | MP3 超 duration.maxMs | `AUDIO_DURATION_LIMIT_UNFIXABLE`；Worker=0 |
| C04 | M4A 合规且页面允许 M4A | 原 File passthrough |
| C05 | M4A 合规但页面只允许 MP3 | AAC-LC decode→MP3；确认、复检、回填 |
| C06 | M4A 超 maxBytes | 输出≤maxBytes；必要时最多两遍 |
| C07 | `moov` 前/后、`stco`/`co64` | 均正确迭代 sample；时长保持 |
| C08 | HE-AAC/ALAC/fragmented/encrypted/raw AAC | 稳定停止；不进入 encoder |
| C09 | 损坏 MP3 帧/M4A table/offset overflow | 有界失败；不分配声明大小缓冲 |
| C10 | 48kbps 以下才可满足 | `AUDIO_TARGET_UNSAFE` |
| C11 | 第一次输出超限 | 仅第二遍；第一遍 decoder/AudioData 全清理 |
| C12 | 第二次仍超限 | `AUDIO_OUTPUT_TOO_LARGE`；不回填 |

### 10.3 资源、安全与回归

| ID | 场景 | 必须断言 |
|---|---|---|
| P01 | ≥30MB MP3 成功 | Worker；UI heartbeat≤500ms目标；有界 PCM；输出复检 |
| P02 | ≥30MB M4A 成功 | 同上；sample table 预算有记录 |
| P03 | MP3/M4A 处理中取消 | ≤1000ms；无迟到结果；AudioData/decoder/Worker/URL 清理 |
| P04 | 成功/取消后第二任务 | 无资源累积；同时 active Worker≤1 |
| S01 | production runtime 网络 | UploadFit 自身外部 codec/audio 请求=0 |
| S02 | storage | 音频/PCM/Base64 持久化=0 |
| S03 | 日志/AI/证据 | 无文件名、路径、PCM、Base64、完整页面文本 |
| G01 | WAV 六组合 | 原 S4 WAV→MP3 全通过 |
| G02 | 图片全量 | `npm run check` 与完整 E2E 无回归 |
| G03 | production IIFE | 无顶层 import/export、动态 import、CDN/远程 Worker |

不得用 fake encoder/decoder 证明 C02/C05/C06/P01/P02。fake 只允许覆盖协议错误分支，并在证据中标为 fake。

## 11. 真实站点门禁

### 11.1 Podcastools

网址：`https://www.podcastools.com/podcast-transcript`

- 先证明英文规则得到 `maxBytes=10000000`、`duration.maxMs=600000`；
- WAV 30/59.5MB 仅作已知回归；
- 新建不超过 10 分钟、超过 10MB 的真实合成 MP3 作为 reencode 正例；
- 当前 30.48/59.39MB MP3 因时长超过 10 分钟，只能作为 duration stop 反例；
- 不点击最终生成/transcribe/提交按钮；记录 UploadFit 处理、回填和 submit=0。

### 11.2 VocaText

网址：`https://vocatext.com/`

- 用非敏感合成 30MB WAV 或 MP3 触发免费版 25MB toast；
- 证明 `File exceeds 25 MB limit.` 被 observer 捕获；
- 规则从 `maxBytes=null` 更新为 25,000,000，`source=rejection`；
- 经确认生成≤25MB MP3，并最多触发一次页面 retry；
- 分开记录 UploadFit 自身网络请求与网页业务上传请求；不得使用真实用户录音；
- 不增加域名 adapter，不从页面 FAQ 全量抽取高可信规则。

### 11.3 M4A 实机

- 在明确允许 MP3且设置 maxBytes 的稳定本地页完成 M4A→MP3；
- 在 Podcastools 使用“不超过 10 分钟、超过 10MB”的非敏感 AAC-LC M4A，验证体积墙下 M4A→MP3、复检和回填；它可与 11.1 共用同一次受控实机窗口；
- 若第三方页面当日因登录、网络、额度或站点改版不可用，只能把该公开站点项记为 `BLOCKED_BY_ENVIRONMENT`；稳定本地页与真实 Tabbit production IIFE 的 M4A 门禁仍必须完成，不能用 mock 替代；
- 真实 Tabbit 证据必须来自当前 production SHA，不得复用 S0/S4 历史 SHA。

## 12. Fixture 与证据纪律

- Git 中只保留小型、无版权风险、可复现的 MP3/M4A/WAV fixture；大型文件禁止提交。
- 每个二进制 fixture 在 `docs/evidence/V2-S4.1/fixture-manifest.json` 记录生成方式、codec/container、duration、sampleRate、channels、bytes、SHA-256、许可/语义来源。
- 本机 ffmpeg 可用于离线生成测试 fixture，但必须在 manifest 明确标记 `FIXTURE_GENERATION_ONLY`；它不能参与 production、pipeline 或能力 PASS。
- 真实大文件可在 Git 外临时生成，验收后删除，只留参数和 hash。
- 不使用改后缀、尾部填充、伪 MP3 header 或假 AAC box 作为成功门禁；畸形 fixture 只能用于失败测试。

## 15. 一票否决

- 仅修改 planner/错误文案，没有真实 MP3/M4A decode；
- `isConfigSupported=true` 但未得到真实 AudioData；
- 主线程整文件 `arrayBuffer()` + `decodeAudioData()`；
- 引入远程 codec/CDN/runtime fetch 或完整 ffmpeg WASM；
- PCM、AudioData 或 M4A sample table 随输入时长无界增长；
- 忘记 `AudioData.close()`，取消后继续输出，或第二遍复用脏 decoder；
- 超过 duration 上限仍通过压缩回填；
- 页面未允许 MP3/无可信 maxBytes 时主动处理；
- toast 监听抓取全页或把成功通知误判为拒收；
- 多 uploader 全局 toast 猜测关联；
- 自动提交或 retry>1；
- 音频/PCM/文件名/Base64 外传、持久化或进入 AI/证据；
- 用伪 fixture、Node ffmpeg pipeline、Chromium debug bundle冒充真实 Tabbit production；
- 图片或既有 WAV Must 回归失败；
- 新依赖许可证/NOTICE/源码替换路径不清楚。
