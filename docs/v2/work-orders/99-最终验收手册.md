# 99 UploadFit V2 最终验收手册

## 1. 验收目标

从未依赖施工 Agent 内存状态的干净环境，独立确认 V2 的产品范围、代码、自动化、真实 Tabbit、200MB 音频、隐私、安全、许可证和发布材料全部闭环。

最终结论只能是：

- `ACCEPTED`
- `REJECTED`
- `BLOCKED_BY_ENVIRONMENT`

不能使用“基本通过”“建议后续优化”替代 Must 结论。

## 2. 验收前置

必须存在：

- V2-S0 至 S4 的 `ACCEPTED` 报告；
- V2-S5 `READY_FOR_ACCEPTANCE` handoff；
- `90-需求追踪矩阵.md` 所有 Must 有真实路径；
- 当前 commit、候选 `dist/uploadfit.js` bytes/SHA；
- S0 编解码/许可 ADR 和依赖 NOTICE；
- S4 Tabbit LR1–LR10 与 200MB 证据；
- S5 release-candidate.json。

缺任一项先 `REJECTED` 或按真实环境状态 `BLOCKED_BY_ENVIRONMENT`，不继续用历史证据补洞。

## 3. 工作区与归档审计

1. `git status --short`：确认没有未说明的生产代码漂移。
2. `git log --oneline -10`：核对阶段提交和候选 commit。
3. 检查 `docs/archive/v1/README.md`：V1 S0–S5 已验收、原 S6 被 V2-S5 承接。
4. 检查 V2 PRD、任务书、handoff、evidence 和 ADR 路径。
5. `rg` 搜索旧绝对 PRD/仓库路径；历史日志可保留，但当前 README/施工入口不能指向已移动路径。

## 4. 干净构建与产物

执行：

```powershell
npm ci
npm run check
npm run test:e2e
npm run build
npm run static-check
git diff --check
```

随后独立计算 `dist/uploadfit.js` bytes/SHA，必须与 release-candidate、S5 handoff、README 发布记录和 S4 实机引用一致。

静态检查：

- 单个 IIFE，可直接粘贴；
- 无顶层或动态 import、export；
- 无 runtime CDN/fetch/远程 Worker；
- 无 eval/new Function；
- 编解码器/WASM 若存在必须内嵌；
- 默认 build 没有 debug/test hook；
- >1.2MB 时存在产品所有者批准 ADR。

连续构建两次，在输入和工具链不变时 bytes/SHA 应一致。

## 5. 依赖、许可与供应链

核对 package.json/lockfile 和打包内容：

- 编解码依赖名称、锁定版本、来源；
- SPDX/许可证原文与 NOTICE；
- 许可证允许当前单文件分发方式；
- 没有安装脚本下载运行时二进制；
- 没有未说明的远程模型、字体、Worker 或 codec；
- ADR 记录增量 raw bytes 和替代/回滚方式。

许可证不清或 NOTICE 缺失为 Must 失败，不以“仅比赛使用”跳过。

## 6. 自动化结果复验

不要只读取施工方截图。独立运行并核对：

- 全量 unit/integration；
- 全量 E2E；
- 音频 planner 边界、48kbps、95% 余量；
- MP3/WAV/M4A 正反 codec；
- 两遍编码上限；
- cancel/late result/cleanup；
- A01–A18；
- 恶意规则/tags/Worker 消息；
- V1 图片全量回归。

测试数量以实际输出为准，不能少于 S5 handoff。失败后先保存完整命令和最小错误，不立即修改代码；验收和返工分离。

## 7. 本地 A–H 交互复验

使用 production bundle 而非 test bundle：

1. A 合规 MP3：不出现无意义压缩确认，原文件 passthrough。
2. B 超限 MP3：展示准确目标参数，确认后复检/回填。
3. C WAV/M4A：格式、大小、有损提示准确，输出 MP3。
4. D 无 max：不处理。
5. E MP3 未允许：不处理。
6. F duration-only：说明压缩不能解决时长，不裁剪。
7. G 处理中取消/移除 input：1 秒内停止，无迟到回填。
8. H 明确拒收：retryCount 最多 1；第二次停止或成功。

每个场景核对 `submit click=0`、外部音频请求=0、事件顺序和 FileList 最终内容。

## 8. 实际 200MB→100MB 独立门禁

不要只引用 S0/S4 历史 JSON。使用仓库生成器重新生成一个不同 seed 的非敏感可解码 fixture：

- input.size > 200000000；
- 页面 maxBytes = 100000000；
- 记录新 input SHA、duration、codec、sample rate、channels；
- 经当前候选确认、处理、最终复检；
- output 为可解码 MP3，`0 < size <=100000000`；
- 时长没有语义裁剪；
- 处理期间 UI 可响应；
- 外部音频请求=0，持久化=0，自动提交=0。

再执行一次中途取消：从点击停止开始计时，1 秒内不再产生处理进度/结果，原文件保留，Worker/object URL 清理。

文件本体不入 Git，验收结束后按生成器说明清理。报告只记录 seed/参数/大小/哈希，不记录绝对路径。

## 9. Tabbit 实机复验

在当前 Tabbit 版本中：

1. 通过官方私有脚本入口粘贴候选 IIFE；仅匹配本地非敏感测试页。
2. 保存/刷新，确认一个 host、一个 active session，无模块/codec 初始化错误。
3. 复验合规 MP3、小型超限 MP3、WAV/M4A 子集。
4. 执行独立 200MB→100MB 门禁。
5. 执行 cancel、明确拒收一次 retry、AI 规则文本路径。
6. 执行图片 S5 场景 A/B。
7. 关闭自动运行并保存，刷新确认不复活；新标签只有一个新 session。
8. 临时脚本不公开，验收页关闭。

如果 Tabbit 不可连接或不具备可控测试页，结论为 `BLOCKED_BY_ENVIRONMENT`。不得以 Playwright Chromium、S0/S4 旧证据、Node 原型或进程存在替代本轮实机。

## 10. 隐私与安全复验

在 DevTools/拦截器/产品诊断中确认：

- 音频 File/Blob/PCM/Base64/文件名不进入 fetch/XHR/WebSocket/EventSource/sendBeacon；
- AI 调用最多包含上传器相关去敏规则文本，不包含音频元数据或名称；
- localStorage/sessionStorage/IndexedDB/Cache/OPFS 不新增音频；
- console、诊断 JSON、截图没有路径、文件名、完整 prompt/响应、脚本 ID、账号；
- CSP/Worker/WASM 失败时停止，不指导用户降低安全设置；
- input.files 回填失败会恢复；不伪造 trusted event；
- 不点击上传、转写、保存、下一步、发布、付款或删除。

## 11. UI 与可访问性

核对：

- 有损、mono、原/目标格式、字节、码率信息准确；
- 开始/取消/停止/关闭按钮同级且键盘可达；
- 处理进度 aria-live 不刷屏；失败为清晰 alert；
- 200% 等效视口不卡住关键操作；
- reduced-motion 生效；
- 恶意外部文字只作为 textContent；
- 关闭后焦点和监听器清理。

## 12. 发布材料一致性

逐项比对 README、说明页、演示脚本、PRD、S0 ADR、测试文档：

- 不写“支持所有音频/网站”“无损”“保证识别率”；
- 格式子集一致；
- 200MB/100MB 使用精确 bytes 说明；
- 当前 bytes/SHA/测试数量/Tabbit 版本一致；
- 安装、更新、关闭可操作；
- 隐私和非目标完整；
- 演示没有把预录/历史 200MB 结果冒充实时三分钟处理；
- 没有未经授权的公开分享或远程推送。

## 13. 最终追踪矩阵审计

`90-需求追踪矩阵.md`：

- V2-FR-001 至 042 均为 ACCEPTED 或有合法 NOT_APPLICABLE ADR；
- V2-NG-001 至 007 均有负向证据；
- 每行代码、测试、证据路径存在且内容支持该行；
- 阶段状态与 handoff/独立验收一致；
- 没有通过删除 requirement 消除失败。

## 14. 判定规则

### ACCEPTED

所有 Must、真实 Tabbit、200MB 门禁、安全/隐私、V1 回归、许可证和发布材料全部通过，无开放阻塞。

### REJECTED

任一 Must 可在当前环境复现失败。必须输出详细返工单，不能由验收方直接把结论写成通过。

### BLOCKED_BY_ENVIRONMENT

同一环境阻塞有明确证据，且不能通过安全只读检查解决。写出版本、时间、错误、已尝试路径和恢复条件；不把产品失败伪装成环境阻塞。

## 16. REJECTED 返工单模板

路径：`docs/handoffs/V2-final-acceptance-rework-order.md`。

每项必须包含：

- 缺陷 ID / 严重级别；
- 对应 PRD/追踪矩阵 ID；
- 精确复现步骤和 fixture；
- 预期、实际和证据；
- 初步根因；
- 允许修改文件；
- 禁止通过降低断言/改文档绕过的说明；

- 施工命令；
- 退出标准和需要重做的 Tabbit LR/证据。

“有问题请继续优化”不是可执行返工单。
