# ADR-005：V2-S0 音频编解码与分发方案

- 状态：`ACCEPTED`
- 日期：2026-08-21
- 范围：V2-S0 隔离能力探针、MP3 编码器选型、单 IIFE 分发和真实 Tabbit 门禁
- 独立验收：2026-08-21 补全后复验通过；结论见 `docs/handoffs/V2-S0-S1-final-acceptance.md`

## 决策

选定 `lamejs@1.2.1` 作为 V2 的 MP3 编码器，严格锁定版本；运行产物保持 Tabbit 可粘贴的单 IIFE、内嵌 Blob Worker、无远程依赖。分发方式冻结为：

```text
单个运行时 IIFE
  + IIFE 内显著第三方声明
  + 同版本可构建 UploadFit 源码/lockfile
  + 完整许可证、NOTICE、来源与替换重建说明
```

因此，Tabbit share link 不是完整发布包。S5 只有在同时提供稳定公开源码/许可证位置时才能正式发布；否则必须移除编码器或停止发布。当前探针和 200MB 证据只证明技术可行性，不构成脱离随附材料分发的批准。

UploadFit 本体继续标记为 `private: true` / `license: UNLICENSED`，没有因为引入第三方库而授予项目级开源许可。这里批准的是 S0/S2 的工程选型与“源码/许可证包随附”的条件式分发模型；S5 不得把裸 Tabbit share URL 当成完整公开发布物。

## 三类候选对比

| 类别与准确实现 | 版本/来源 | 许可事实 | 体积 | 流式、Worker 与性能 | 结论 |
|---|---|---|---|---|---|
| 浏览器原生 WebCodecs | Tabbit 1.10.16.0，Chrome/150 UA | 浏览器 API；无新增分发依赖 | 0 增量 | `AudioEncoder.isConfigSupported({codec:'mp3', 48kHz, 2ch, 128kbps})` 在真实 Tabbit 返回 false；MP3/AAC-LC/Opus decoder 为 true。不能输出 PRD 固定 MP3 | `REJECTED_FOR_MP3_ENCODING` |
| 轻量纯 JS：`lamejs` | `1.2.1`；<https://github.com/zhuker/lamejs/tree/v1.2.1> | npm 声明 `LGPL-3.0`；上游根 LICENSE 为 424-byte 说明，包内另含历史 GNU Library GPL v2 文本；全部如实保留 | 上游 `lame.min.js` 156,043 bytes；最终双上下文探针 353,484 bytes，其中声明 220 bytes；可执行 payload 353,264 bytes | `encodeBuffer()` 分块 PCM、`flush()`；Blob Worker 实测；200,000,044-byte 输入单遍输出 20,834,880 bytes，heartbeat 189ms | `SELECTED_WITH_RELINKABLE_SOURCE_DISTRIBUTION` |
| 内嵌小型 WASM：`wasm-media-encoders` | `0.7.0`；<https://github.com/arseneyr/wasm-media-encoders> | 包/仓库声明 MIT，但 MP3 payload 是 LAME 编译物；本轮未取得比选定方案更清晰的 LAME 对应源码/分发链 | 上游记录 MP3 JS 3.3KiB、WASM 130KiB、combined gzip 66KiB；Base64 内嵌约增加 30%；未生成 UploadFit 精确 IIFE | `encode(Float32Array[])` 可重复分块、`finalize()`；可在 Worker 内包装；未执行 Tabbit 200MB，切换会使现有证据失效 | `REJECTED_LICENSE_AND_RETEST_COST` |

否决对照：`@ffmpeg/core@0.12.10` 为完整 FFmpeg WASM core，包声明 `GPL-2.0-or-later`，需要额外 core/WASM 资产且体积和内存显著超出轻量 S0 方案；只作 `OUT_OF_SCOPE_REFERENCE`，不计入上述三类轻量候选。

维护事实：`lamejs@1.2.1` 是 npm 当前版本但已经多年未发布；选择它的依据是已通过本机最终 Tabbit/200MB 门禁和较小可执行体积，不把“仍为 latest”解释成活跃维护。回滚时删除 S0/S2 编码器模块、探针和相应 NOTICE；若更换编码器，必须重新执行 codec、Tabbit 和 200MB 门禁。

## 许可证与可重新组合条件

### 上游事实

- 包元数据：`LGPL-3.0`；
- 包根 `LICENSE`：424-byte 商业使用说明，并建议把 `lame.min.js`/`lame.all.js` 作为单独库链接；
- 包内 `src/main/java/COPYING`：历史 GNU Library GPL Version 2 文本；
- UploadFit 没有修改上游源码，但 esbuild 会把发布的 minified 文件转换并嵌入组合 IIFE。

因此不得再把 424-byte 文件称为“完整 LGPL 原文”，也不得把当前物理产物称为“separate linked asset”。工程采用保守披露：保存包声明对应的完整 LGPLv3/GPLv3、上游短说明、包内历史 COPYING 和全部来源/hash。

### UploadFit 分发约束

`docs/evidence/V2-S0/licenses/RELINKING.md` 定义可执行路径：发行包携带完整 buildable application code、精确 lockfile、许可证、NOTICE 和替换步骤，并明确允许接收者为替换/调试 LGPL 组件而修改/reverse-engineer 相应组合代码。`scripts/audio-probe/build.mjs` 从可替换的 `node_modules/lamejs/lame.min.js` 读取编码器；替换后可重新生成 IIFE。

正式发布前仍建议由项目所有者/法务复核。若发行方不能保留这些材料和权限，许可证门禁失败，不得发布含 `lamejs` 的脚本。本 ADR 是工程合规方案，不是法律意见。

## 探针实现

```text
File.slice()（选定 256KiB PCM chunk）
  -> bounded WAV header parser
  -> Worker 内 PCM16/24/32 转 Int16、必要时 stereo->mono
  -> lamejs 分块 MP3 编码
  -> transferable MP3 chunks
  -> Blob
  -> 独立 MP3 帧扫描 + AudioDecoder 首帧抽检 + SHA-256
```

不使用整输入 `file.arrayBuffer()`、`decodeAudioData(await file.arrayBuffer())`、Node/本机 ffmpeg、远程 API/CDN 或持久化音频。输出 Blob 必须在主线程聚合，这是浏览器最终文件交付的必要缓冲；输入 PCM 始终有界。

## 实证结果

- 真实环境：Tabbit `1.10.16.0`，Chrome/150 UA，remote CDP `9222`；
- 输入：200,000,044-byte PCM32 WAV，时长 520,833.333ms；
- 计划：320kbps、mono、safe target 95,000,000 bytes；
- 输出：20,834,880-byte `audio/mpeg`，完整扫描 21,703 帧，媒体时长 520,868.8ms，首帧独立 AudioDecoder 解码 1,152 frames；
- Worker：true；单遍；256KiB 输入块；最大 heartbeat gap 189ms；保守峰值缓冲上界 62,832,320 bytes；
- 取消：Worker 创建并投递任务后立即取消，Worker terminated、Blob URL revoked、无半成品持久化；
- 外部音频请求 0、持久化 0、用户录音 0。

旧证据的 `runtime.durationMs=520868.8` 是输出媒体时长，不是处理墙钟耗时。本轮更名为 `output.durationMs`/`verification.durationMs`，并把未采集的 `runtime.processingElapsedMs` 如实写为 null。S2 production-equivalent 200MB 门禁必须采集真实 processing elapsed time，不得再次混用。

## 声明后构建同一性

补入显著第三方声明后的探针：

- 最终 IIFE：353,484 bytes；SHA-256 `878ABD08E561E627E9C3024C367ADA4036F9C481AC304FE8617DC2D9C0B4EAED`；
- 声明前缀：220 bytes；
- 剥离纯注释前缀后的 executable payload：353,264 bytes；
- executable payload SHA-256：`342F301006D05FD5950EB4CD8ED1F66EEC9E7E8C56280D211616B3995E3AD4C8`。

payload bytes/SHA 与完成真实 200MB 门禁的版本逐字节相同，因此不重复大文件。声明后的构建只需小文件运行烟测；如编码器或 payload 发生变化，必须重跑完整门禁。

## S2 绑定条件

S2 必须：

1. 继续精确使用 `lamejs@1.2.1`，不得临时换包；
2. 将同类显著 notice 加入 production IIFE；
3. 保持 `RELINKING.md` 所列可替换构建路径；
4. 为 MP3/M4A 解码路径单独验证 demux/streaming，不把 `isConfigSupported` 当成完整转码证明；
5. production-equivalent 200MB 门禁记录 `processingElapsedMs`；
6. S5 发布包提供稳定公开源码/许可证位置，否则不得公开 detached Tabbit script。
