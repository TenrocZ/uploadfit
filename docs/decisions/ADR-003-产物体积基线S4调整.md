# ADR-003：取消生产脚本固定体积门禁

- 日期：2026-08-19
- 状态：已采纳（用户/产品负责人最终裁决）
- 取代：150,000-byte 原始硬门禁，以及本 ADR 早期提出但未获批的 168,000-byte 过渡方案

## 背景

S4 完整 Must 范围使单文件生产 IIFE 超过早期 150,000-byte 目标。Tabbit 官方界面没有声明固定上限；2026-08-19 实机又成功保存并运行了 172,028-byte 验收脚本，其中包含 169,536-byte 最终生产 bundle。继续用本地自设字节阈值阻断，会把平台未施加的限制误写成产品红线。

## 决定

1. `dist/uploadfit.js` 不设置固定 KB/bytes 上限，体积不参与验收退出码。
2. 每次生产构建仍记录 minified raw bytes、SHA-256 和相邻构建差异，防止无界膨胀或不可复现。
3. 以下发布条件继续是硬门禁：
   - 单个 minified JavaScript IIFE；
   - 可在 Tabbit “脚本”编辑器直接粘贴、保存和运行；
   - 无 ESM import/export、source map、运行时远程 chunk、CDN、远程字体或第三方运行时依赖；
   - 静态安全检查和全部行为测试通过；
   - 重复运行、清理、隐私和副作用边界保持成立。
4. 体积优化保留为非阻断工程指标；不得为了减字节削弱安全校验、可访问性、错误解释或 S4 Must 功能。

## 实施

- 删除 `src/config.js` 的 `BUILD_LIMIT_BYTES`。
- `scripts/static-check.js` 只报告 artifact bytes，不因大小返回失败。
- PRD、共享契约、S5/S6 任务书、需求追踪矩阵和最终验收手册同步为“记录、不设固定门槛”。
- 最终 S4 产物：169,536 bytes，SHA-256 `67879C73748432DEAF7526ED645842575EAE36AD710313082BCF38B2003AE840`。

## 验证

- `npm run check`：18 个 Vitest 文件、148 个用例通过，static-check 通过并输出实际字节数。
- `npm run test:e2e -- --reporter=line --workers=1`：90/90 通过。
- Tabbit 1.10.16.0：172,028-byte 临时验收脚本成功保存、自动运行并调用官方 `LLMBridge.chat()`；证据见 `docs/evidence/S4/tabbit-ai-result.json`。
