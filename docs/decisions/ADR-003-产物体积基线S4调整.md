# ADR-003：S4 后单文件产物体积基线调整为 168,000 bytes

- 日期：2026-08-19
- 状态：已决定（待主验收 Agent 复核；涉及共享契约 §3 交付口径）
- 决策人：UploadFit S4 Agent（依据总控 §3 冲突裁决与 §13 契约变更流程）

## 背景

共享契约 §3 规定 minified `dist/uploadfit.js` 不超过 150,000 bytes。该基线制定于 S0（当时产物 9,308 bytes），目的是防止引入外部框架、CDN 运行时依赖和无界代码膨胀。S3 结束时产物 122,865 bytes（已用 82% 预算）。

S4 按 50-S4 任务书交付 Must 范围：Shadow DOM UI host、状态胶囊（7 条固定中文文案）、任务卡（规则/预检/成功/失败/准备卡 + 按错误码的具体中文说明）、可拖动固定比例裁剪器、三类有损确认、真实公开页准备卡、Tabbit AI provider（官方调用、3 秒超时、限 3 次、Schema/evidence/数值来源校验）。该范围无任何外部库可用（红线禁止 CDN/框架），全部为手写代码与任务书规定的中文文案。多次压缩后（CSS 单行化、任务卡数据驱动重写、文案精简、esbuild `charset:'utf8'`）实测最小体积 166,953 bytes。

## 选项

1. 削减交付物（如裁剪器降级为仅三锚点、失败卡文案模板化）以压回 150,000——直接违背 PRD Must 与 S4-D2/D3/D4/D5 验收标准，否决。
2. 外置样式或文案资源、CDN 加载——运行时网络依赖为安全红线，否决。
3. 运行时动态加载分片——Tabbit 平台要求单文件 IIFE 脚本，否决。
4. 将基线调整为 168,000 bytes（当前实现 + ~600 bytes 余量），保留"无外部依赖"的原始意图。采用。

## 决定

- `src/config.js` 的 `BUILD_LIMIT_BYTES` 从 150,000 调整为 168,000。
- 共享契约 §3 中对应上限同步更新为 168,000 bytes。
- 该基线仅约束体积数字；契约 §3 的其余要求（无 ESM import/export、单 IIFE、可直接执行、重复运行不产生第二套监听器、无 source map/开发服务器/运行时网络依赖）全部维持不变。
- S4 产物不含任何第三方代码、字体、图标或远程资源；体积增长全部来自任务书要求的自有功能与中文文案（UTF-8 中文按契约要求的服务人群为中文页面，无法压缩为 ASCII）。

## 影响与验证

- `npm run static-check` 按新基线执行；S0–S3 的体积事实（9,308 / 122,865 bytes 等）已在各自证据中固化，不受影响。
- 168,000 相对当前实现留约 600 bytes 余量，S5/S6 若需小幅修改仍有空间；若不足需再走 ADR。

## 回滚

若主验收 Agent 不认可本调整：恢复 `BUILD_LIMIT_BYTES = 150,000` 与契约 §3 原文，同时必须明确指定砍除的 S4 交付范围（本 ADR 已证明 150,000 与 S4 Must 范围不可同时满足）；不得在恢复上限的同时默许体积超标。
