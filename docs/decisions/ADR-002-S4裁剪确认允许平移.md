# ADR-002：S4 裁剪确认允许在保持建议尺寸的前提下平移

- 日期：2026-08-19
- 状态：已决定（S4 范围内实施；涉及 S2 文件的越界公共修复）
- 决策人：UploadFit S4 Agent（依据任务书 50-S4 §8.1 与总控 §6 越界修复条款）

## 背景

S2 的 `resolveProcessingConfirmation`（src/image/planner.js）与 `processImage` 的权威计划复验（src/image/canvas-pipeline.js `validateResolvedPlan`）要求 CROP 确认 payload 必须与 `proposedCrop` **逐字段相等**（x/y/width/height 全等）。该设计用于 S2 防篡改：外部传入的计划不能夹带任意裁剪矩形。

S4 任务书 §8.1 要求裁剪器支持"鼠标拖动图片或裁剪框，边界不超图像；默认居中；可降级为顶部/居中/底部三锚点；确认后返回归一化 {x,y,width,height}"。用户拖动后确认的矩形与建议矩形**位置不同**（尺寸相同），在 S2 严格相等校验下会被拒绝（`USER_CONFIRMATION_REQUIRED` / "Crop confirmation payload is invalid or tampered"），导致任务书要求的交互无法实现。

## 选项

1. UI 层接受拖动但确认时仍提交原建议矩形——违背"不静默裁"红线（用户拖到 A 处、实际裁 B 处），否决。
2. 只做锚点降级（顶部/居中/底部），拖动不生效——仍需放开 y 方向平移，本质相同，且不满足"鼠标拖动"Must 项，否决。
3. 放宽两处校验：允许与建议矩形**同尺寸**（width/height 逐字段相等）的平移矩形（x/y 为有限非负整数），边界由 canvas-pipeline 现有 `safeCrop` 在渲染期强制。采用。

## 决定

- `planner.js` `resolveProcessingConfirmation` 的 CROP 分支：payload 必须满足 width/height 与 `proposedCrop` 完全相等，x/y 有限且 ≥0；不再要求 x/y 相等。
- `canvas-pipeline.js` `validateResolvedPlan` 的 CROP 分支同步放宽为相同判据（尺寸相等 + 平移合法），渲染期 `safeCrop` 继续负责"矩形不超出解码图像"的硬校验（越界抛 `PROCESSING_FAILED`）。
- 裁剪框尺寸仍完全由规则推导（目标比例的最大内接矩形），UI 不提供改尺寸入口：目标比例是规则约束，不允许用户通过裁剪 UI 规避。
- 归一化矩形（0–1）只作为 cropper 对外 API 的输出单位；进入确认 payload 前由 UI 换算回源图像素坐标。

## 契约符合性

共享契约 §7 只要求 `resolveProcessingConfirmation` "校验 confirmation id/type/payload 后返回新计划"，未规定 payload 必须等于建议矩形；契约 §5.3 只要求三类有损确认未决时计划不可执行。本决定未降低任何安全条件：裁剪仍必须显式确认、尺寸仍由规则锁定、越界矩形仍被拒绝。无需修改契约文件。

## 影响与回归

- S2 现有测试（`planner.test.js`、`image-pipeline.test.js`、`s2-rework.test.js` Q-S2-001 的 tampered 用例篡改的是 UPSCALE payload，不涉及 CROP 平移）均以"等于建议矩形"的 payload 断言，放宽后语义向后兼容，无需改动。
- S3 闭环不受影响：确认流程、重试、提交边界未触碰。
- 新增 S4 测试 U05/U06 覆盖平移确认与取消路径。

## 回滚

若最终验收不认可本放宽，恢复 planner.js 与 canvas-pipeline.js 两处 CROP 判据为 `stableEqual(crop, proposedCrop)`，并移除 S4 cropper 的拖动入口（保留三锚点降级也会一并失效，需回到仅居中建议矩形模式）。
