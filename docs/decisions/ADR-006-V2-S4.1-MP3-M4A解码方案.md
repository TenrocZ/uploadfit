# ADR-006 V2-S4.1 MP3/M4A 解码方案

- 状态：`ACCEPTED`
- 日期：2026-08-25
- 阶段：V2-S4.1
- 迁移来源：ADR-005 的 `lamejs@1.2.1` 编码器继续冻结；本 ADR 只迁移“可进入编码器的输入边界”

## 1. 决策

采用浏览器原生 `AudioDecoder`，配合 UploadFit 内部、只覆盖冻结子集的有界 MP3 frame iterator 与 ISO BMFF/M4A demuxer。压缩输入通过 `File.slice()` 读取；encoded chunk 在 production 等价 Dedicated Blob Worker 内解码；每个 `AudioData` 复制成现有 lamejs 接受的有界 Int16 chunk 后立即 `close()`。输出继续使用 ADR-005 已验收的 `lamejs@1.2.1`，不得增加远程 runtime 或主线程整文件解码回退。

Planner 只有在本方案的真实 Tabbit Worker gate、production integration 和最终验证均通过后，才可让合法超限 MP3 与冻结子集 AAC-LC M4A 形成可执行计划。runtime capability、container/profile 或资源预算不成立时继续稳定停止。

## 2. 已评估选项

### A. 原生 WebCodecs + 内部最小 demuxer（采用）

- `AudioDecoder` 负责 MP3/AAC-LC 解码；UploadFit 只实现 MP3 frame 边界和 M4A sample table 到 `EncodedAudioChunk` 的映射。
- 优点：不新增第三方依赖；单 IIFE 内只增加必要容器逻辑；原生 decoder 位于 Blob Worker；PCM 可逐帧关闭；供应链与包体最小。
- 风险：User Agent 能力不可仅靠 `isConfigSupported()` 推断；必须真实投递 chunk。M4A 表解析必须自行承担整数溢出、范围交叉验证和资源上界。

### B. 只依赖原生 WebCodecs、不实现 demux（否决）

- `AudioDecoder` 不接收 MP3/M4A 容器，仍需要调用者提供正确的 encoded access unit、timestamp、duration 和 AAC AudioSpecificConfig。
- 把完整 MP3/M4A 直接作为单个 chunk、使用 `decodeAudioData()` 或浏览器媒体元素抽取 PCM 均不满足流式、有界 Worker 和确定性 sample table 要求。

### C. 第三方 demux 库（本阶段否决）

- 评估方向包括通用 ISO BMFF 库（如 mp4box.js）或同时覆盖多容器的媒体库。
- 优点：box/sample table 覆盖面更广；缺点：支持面显著超出冻结子集、包体和攻击面更大、单 IIFE notice/relinking 审计更复杂，仍不能替代真实 Tabbit `AudioDecoder` 门禁。
- 当前内部 parser 已能以较小代码覆盖 Must 表；因此不引入。若后续发现 Must 表无法安全覆盖，必须新 ADR 重新审查固定版本、来源、许可证、NOTICE、增量 bytes 和回滚方案。

完整 FFmpeg/WASM 或软件 AAC/MP3 decoder 不在候选内：它会扩大包体、许可证、内存和性能风险，也违反本阶段禁止引入完整 FFmpeg 工具链的约束。

## 3. 真实 Tabbit Worker gate

环境：Windows 10/11，Tabbit Browser Chrome `151.0.0.0` user agent；本地安全上下文 `http://127.0.0.1:8765`；Dedicated Blob Worker；任务会话 `uploadfit-s4-1`。证据不得记录 Tabbit 私有脚本 ID、文件名、PCM 或 Base64。

`isConfigSupported()` 仅为前置：Worker 内 `mp3` decode、`mp4a.40.2` decode 与 AAC-LC encode 报告 supported。决定性 gate 使用真实非敏感合成数据：

| 项目 | 首次 | 同 Worker 再次运行 | 清理 |
|---|---:|---:|---|
| MP3（frozen lamejs Worker 生成） | 33 个 `AudioData` / 38,016 frames / 48kHz / mono | 同样 33 / 38,016 | decoder closed；未关闭 `AudioData=0` |
| AAC-LC M4A（Worker `AudioEncoder` + 内部非 fragmented muxer） | 48 个 `AudioData` / 49,152 frames / 48kHz / mono | 同样 48 / 49,152 | decoder closed；未关闭 `AudioData=0` |

M4A gate 为 `moov` after `mdat`、`stco`、48 个真实 AAC access unit；MP3 使用 257-byte `File.slice()` 强制跨 slice 残留恢复，最大残留 305 bytes。M4A 最大单次 slice 751 bytes；两类 `maxDecodeQueueSize` 均不超过 2。取消返回 `CANCELLED`，无迟到消息，清理状态为 decoder closed / 未关闭 `AudioData=0`；无效 MP3 chunk 在该 Chromium 中被 decoder 静默丢弃，UploadFit 以 flush 后零输出稳定判为 decode failure。fixture 哈希、bytes 和完整脱敏结果写入 `docs/evidence/V2-S4.1/`，不保存二进制。

说明：`about:blank` 的非安全上下文不会暴露 Worker WebCodecs，该无效预检不作为能力失败；最终 gate 只引用本地安全上下文结果。

## 4. 冻结支持子集

### 4.1 MP3

- MPEG Layer III；MPEG-1/2/2.5 中实际 sample rate 为 32/44.1/48kHz 的常见子集；mono/stereo。
- CBR；带有效 Xing/VBRI 的 VBR，或在有界 slice/frame scan 内可完整验证的 VBR。
- 每帧验证 version/layer/bitrate/sampleRate/channels/frameLength；timestamp/duration 来自累计 sample count。
- ID3v2 只跳过合法、受限 tag；跨 slice residual 固定上界；截断、free-format、非 Layer III、采样率/声道中途漂移稳定停止。

### 4.2 M4A

- ISO BMFF/M4A；唯一 `soun` track；AAC-LC `mp4a.40.2`；mono/stereo；32/44.1/48kHz。
- 非加密、非 fragmented；`moov` 可位于 `mdat` 前或后；支持 `stco`/`co64`；交叉验证 `stsd/esds/stts/stsc/stsz`、chunk/sample offset 与合法 `mdat`。
- `esds` 的 AudioSpecificConfig 原样传入 `AudioDecoderConfig.description`；只接受 audio object type 2。
- 当前冻结不接受：HE-AAC/HE-AACv2、ALAC、`enca`/DRM、`moof`、raw ADTS `.aac`、三声道及以上、多音轨/含视频且不能唯一确定音轨、edit list 导致时长不确定、异常 timescale、损坏/重叠/溢出表。

### 4.3 WAV 与输出

- 既有 PCM WAV 16/24/32-bit、mono/stereo 行为不变。
- 目标仅为 MP3；同一任务最多两遍，每遍重新创建 decoder/encoder；最终 MP3 仍须通过签名、完整帧、bytes、duration、sample rate/channels 与代表帧真实解码验证。

## 5. 资源上界

| 资源 | 硬上界/策略 |
|---|---|
| 输入 slice | 生产默认不超过 4MiB；M4A box header 使用 16-byte slice |
| MP3 residual | 4KiB；超过即 `AUDIO_DECODE_FAILED` |
| `moov` / container table bytes | `moov` 最多 8MiB；累计表解析预算最多 16MiB |
| sample/chunk/table entries | 每类最多 1,000,000；乘加全部使用 safe-integer/文件范围校验 |
| `AudioDecoder.decodeQueueSize` | 最大 8；达到上界即等待 dequeue/flush，不继续投递 |
| 未关闭 `AudioData` | 逐个复制后立即 close；异常/取消 finally close；目标 0 |
| PCM | 继续受 `AUDIO_PCM_BUFFER_BUDGET=32MiB` 约束；不完整展开输入 |
| encoder output | 每遍只保留 MP3 chunk collector；受页面 target 与固定超限余量约束；不得与完整 PCM/完整输入同时常驻 |
| progress | `demux/decode/encode/validate`；单调且不高于 10 次/秒 |

这些上界将在 production 测试与实机资源证据中以实际最大值补充；不得为了通过测试取消或扩大为随输入增长的无界结构。

## 6. 取消、错误与回退

- `CANCEL` 设置当前 task 的 cancellation token；停止继续 slice/decode/encode，关闭 decoder 和所有待处理 `AudioData`。主线程现有 deadline 仍为 1 秒，超时强制 terminate Worker。
- decoder callback、flush rejection、零 `AudioData`、截断帧、损坏 box/table 或 capability 缺失均映射稳定错误码，不跨线程传原始异常、box/tag 内容、路径或堆栈。
- 第二遍编码重新建立完整 demux/decoder/encoder 状态；不得复用第一遍的 queue、timestamp 或 AudioData。
- CSP/Worker/WebCodecs 不可用时停止为 `AUDIO_WORKER_UNAVAILABLE` 或 `AUDIO_CODEC_UNSUPPORTED`；不退回主线程整文件 decode。

## 7. 依赖、许可与包体

- 新生产依赖：无。
- 原生 WebCodecs：浏览器 API，不随 bundle 分发第三方源码。
- 内部 demux/frame iterator：仓库自有实现；不增加第三方 NOTICE/relinking 义务。
- 既有编码器：`lamejs@1.2.1`，LGPL-3.0 notice/source/relinking 路径继续使用 ADR-005 与 `docs/evidence/V2-S0/licenses/`，版本和来源不变。
- S4.1 开工 baseline production：421,333 bytes，SHA-256 `98BD12C651C2801E2E2E8BC9C2A006057024AA26E2D916B33899487B9A0F1A68`。
- Batch A（英文规则/transient observer，尚未加入 production decoder）production：423,323 bytes，SHA-256 `23CB34F143E86BE0F5CCD86EC488E884421565EB17682A3B9F610F72A68AEE97`，相对 baseline `+1,990` raw bytes。
- S4.1 最终 production：444,989 bytes，SHA-256 `EB77F23278CBCEB739376671D0C1AEEEAC417309DD346EB40CEC2FE99729E030`，相对开工 baseline `+23,656` raw bytes；体积按产品裁决仅留痕，不设上限门禁。
- 最终新增生产依赖仍为 0；`lamejs@1.2.1` 及其 ADR-005/NOTICE/relinking 义务不变。

## 8. ADR-005 迁移与回滚

ADR-005 的 encoder/version/license/Worker-only/streaming/48kbps/两遍边界全部保留。被迁移的唯一结论是“只有 PCM WAV 可进入 encoder”：在本 ADR gate 和 production 测试通过后，合法 MP3/AAC-LC M4A 可先在同一 Worker 解码成有界 PCM，再进入同一个 frozen encoder。

回滚顺序：

1. 移除内部 MP3/M4A demux/decoder 与 Worker 分支；
2. 恢复 planner 对超限 MP3/M4A 的 `AUDIO_CODEC_UNSUPPORTED` 安全停止；
3. 保留 Batch A 的通用英文规则与 transient rejection 修复（两者不依赖 codec）；
4. 重建 production IIFE，复跑 WAV/图片回归并记录回滚 bytes/SHA。

不得通过保留 planner 解禁、删除 decoder 或改低测试断言进行“部分回滚”。
