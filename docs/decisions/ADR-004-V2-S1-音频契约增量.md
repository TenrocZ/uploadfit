# ADR-004：V2-S1 音频发现与元数据契约增量

- 状态：`ACCEPTED`
- 日期：2026-08-20
- 范围：V2-S1 规则、媒体分类和有界元数据读取
- 前置：V2-S0 与 ADR-005 已于 2026-08-21 独立验收通过

## 背景

V1 的 `RuleSet` 只覆盖图片。V2-S1 需要在不改变既有图片字段语义的前提下，识别音频上传器、保存页面音频规则，并将二进制签名元数据交给后续 S2/S3。V2-S0 的真实 Tabbit 探针已经独立验收通过，本 ADR 只批准 S1 契约增量。

## 决定

1. `RuleSet` 增加可选 `mediaKind`、`duration` 和 `audio` 字段；旧图片字段和校验保持兼容。
2. 音频扩展名规范化为带前导点的 `.mp3`、`.m4a`、`.aac`、`.wav`、`.webm`；MP3 的规范 MIME 为 `audio/mpeg`。
3. S1 仅实现任务书冻结假设中的 MP3、PCM WAV（16/24/32 bit，单/双声道）和 AAC-LC M4A。WebM/Opus、裸 AAC、压缩 WAV 以及伪造/截断容器稳定停止。
4. `inspectAudio()` 只读取不超过 1 MiB 的头/尾 `slice()`，返回不含文件名、标签、原始字节的 `AudioMetadata`；S1 不创建 Worker、不编码、不回填。
5. 只有明确 MP3 证据与 `maxBytes` 同时存在时，音频规则才标记为可执行；duration/采样率/声道等字段不生成裁剪或分段计划。

## 影响

- V1 图片解析、校验和运行时行为保持不变；已有图片测试全量通过。
- S2 可直接消费 `src/audio/metadata.js` 与 `src/audio/validators.js` 的公开接口，并在独立确认后实现计划/编码。
- S0 证据当前冻结为 `lamejs@1.2.1` 探针、PCM16/24/32 WAV、MP3 和 AAC-LC M4A 元数据子集；若独立验收否决任一子集，只需回滚本 ADR 对应的音频模块和 `mediaKind` 分支，不影响图片字段。
- 本 ADR 不批准 S0 编解码能力；S0/S1 都必须由主验收方独立确认。
