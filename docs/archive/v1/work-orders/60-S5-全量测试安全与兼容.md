# 60 S5：全量测试、安全与兼容

## 1. 阶段使命

以独立 QA 视角验证 S0–S4 的集成结果，建立稳定测试页、完整自动化、Tabbit 实机记录、安全审计和性能/体积证据。本阶段不以“帮功能凑绿”为目标：发现问题要归因、修复、回归并记录，不能修改断言来掩盖需求失败。

## 2. 前置条件

- S0–S4 均提交 `READY_FOR_ACCEPTANCE` handoff。
- 本地单测、构建和阶段集成测试为绿色。
- 可用最新版 Tabbit PC 浏览器和官方 AI 能力。
- 所有测试使用非敏感 fixtures，不进入真实报名最终提交。

## 3. 文件范围

- `test-pages/index.html`、`scenarios.js`、`styles.css` 及必要静态资源。
- `tests/e2e/*`。
- 跨模块 `tests/integration/*`。
- 安全、性能、体积检查脚本。
- `docs/test-results.md`、`security-review.md`、`performance.md`。
- `docs/evidence/S5/*`、`docs/handoffs/S5-handoff.md`。

发现产品缺陷时：

1. 先写能失败的回归测试。
2. 优先交回对应阶段所有者修复。
3. 若由 S5 直接修复，交接逐文件说明越界原因。
4. 修复后运行完整回归，不只跑单个测试。

## 5. 六个稳定测试场景

测试页可以使用路由/query 切换场景，但必须可以从首页一键进入。页面自身显示接收到的事件和文件元信息，便于评委肉眼核对。

### 场景 A：预检适配

- 明示：“仅支持 JPG，30–120KB，390×567像素”。
- input 的 accept 故意只写 `image/*`，逼迫脚本读取附近文本。
- 选择约 2MB、1170×1701 PNG。
- 页面展示每次 input/change、`isTrusted`、MIME、字节、宽高。
- 预期：原不合规文件不进入页面上传逻辑；新 JPEG 为 390×567、30720–108000 bytes。

### 场景 B：明确拒收后重试

- 初始只写“上传证件照”。
- 选择超大/PNG 后动态显示“仅支持JPG且不能超过100KB”。
- 页面模拟“选择即上传”，按 change 事件自动校验。
- 首次拒收和后续事件次数清晰显示。
- 预期：规则从拒收补充，处理后自动重新分发事件一次；页面接受；retryCount=1。

### 场景 C：需要裁剪

- 要求 3:4 或 exact 390×520。
- 上传明显横图。
- 预期：出现固定比例预览；确认后输出正确；取消/Esc 时 input 仍为原文件。

### 场景 D：模糊错误

- 选择文件后只显示“上传失败，请稍后重试”。
- 预期：process/inject/retry 调用均为0；文件集合不变；UI 解释未修改原因。

### 场景 E：表单型

- 选择文件后不自动上传，页面有“提交测试”按钮和独立 click 计数。
- 预期：UploadFit 只替换文件并提示用户；按钮 click 计数始终0，直到测试员亲自点击。

### 场景 F：官方工具要求

- 明示“必须使用照片审核处理工具”。
- 预期：`OFFICIAL_TOOL_REQUIRED`，不 process、不 inject、不声称成功。

## 6. 测试页实现要求

- 页面模拟逻辑与 UploadFit 源码完全分离，不导入私有业务函数。
- E2E 通过真实 file chooser/input 和 DOM 事件交互，不直接调用 controller 绕过入口。
- 页面可用结构化 `data-testid`，但视觉文本与评委路径真实。
- 页面记录事件次数、顺序、`isTrusted` 和文件元信息，不记录图片内容。
- 每个场景可重置，重置后无上次 observer/task 状态。
- 页面本身不得向网络上传 fixture。
- 支持在本地静态服务器和发布后的 HTTPS 地址运行。

## 9. 安全审计

### 9.1 静态检查

检查 `src` 和生产构建：

- 无 `eval`、`new Function`、动态远程脚本。
- 无对业务页面文本使用 `innerHTML/outerHTML/insertAdjacentHTML`。
- 无 Cookie、Token、密码、其他表单值读取。
- 无 `fetch/XMLHttpRequest/WebSocket/sendBeacon` 劫持；平台 AI 官方调用单独审查。
- 无对网页保存/提交/发布/付款/删除按钮调用 `click()`。
- 无硬编码 API key、Bearer token、私钥。
- 无运行时 CDN URL 和未登记依赖。
- 日志不含文件名、Base64、完整页面文本、URL 查询参数。

任何静态命中都人工检查并在 `security-review.md` 逐项解释，不因“是测试代码”自动忽略生产打包风险。

### 9.2 动态检查

- 拦截浏览器网络，普通扫描/处理/回填期间图片二进制请求数为0。
- AI 调用只包含脱敏相关文本，不含 File、文件名、Base64和其他字段。
- 模糊错误、官方工具、规则冲突不产生 image/injection 副作用。
- UI 注入恶意网页文本（HTML、脚本、事件属性）只按纯文本显示。
- dispose 后 mutation 不再引发日志/任务。
- object URL 创建/释放计数最终平衡；Worker 全部 terminate。
- 生产构建不暴露敏感 debug 快照。

## 10. 性能与体积

参考 PC、最新版 Tabbit、4000×3000 左右 ≤10MB JPEG：

- 总处理时间 ≤5秒，理想≤3秒。
- 主线程连续冻结不得 >500ms，目标≤150ms。
- DOM mutation 合并 100ms，不随页面变化反复全量扫描 body。
- 同时只一个处理任务，快速选择不会叠加内存峰值。
- minified `dist/uploadfit.js` 记录 raw bytes、SHA-256 和相邻构建差异；不设置固定体积上限，不因字节数单独阻断。

`docs/performance.md` 写清 CPU/内存、Node、Tabbit/Chromium版本、样本规格、Worker模式、重复次数、P50/P95 或至少三次结果。不能只写“感觉很快”。

## 12. 缺陷分级

| 级别 | 示例 | 放行 |
|---|---|---|
| P0 | 数据外传、自动提交、无限重试、Tabbit不能回填 | 绝不放行 |
| P1 | Must主流程失败、静默有损、AI无校验、复检绕过 | 绝不放行 |
| P2 | Should兼容、性能超目标但未超硬线、局部可访问问题 | 修复后回归；主 Agent决定 |
| P3 | 轻微文案/视觉、不影响理解和操作 | 可记录，但不得影响演示 |

测试失败必须保留复现与修复记录。禁止删除失败用例或降低断言来“完成阶段”。

## 13. 阶段退出标准

- 所有阶段测试和 E01–E15 为 PASS；X01–X12 中 Must 项 PASS、Should 项有明确结论。
- 六场景测试页在本地和目标公开环境行为一致。
- Tabbit 实机矩阵无 Must 空白，真实 AI 与回填都有证据。
- P0/P1/P2 未解决缺陷为0；P3不影响演示和理解。
- 安全审计无未解释命中；普通图像流程网络外发为0。
- 性能与体积达到硬门槛。
- 关闭/导航/失败路径均证明资源清理。
- `docs/test-results.md`、`security-review.md`、`performance.md` 完整。
- 完整 `npm ci → check → test:e2e` 从干净环境通过。

## 14. 禁止事项

- 不使用真实个人证件照或真实报名提交做测试。
- 不把 mock AI、Chromium 对照或本地页面代替 Tabbit 实机。
- 不跳过失败用例、不改松断言、不伪造截图。
- 不因页面“看起来成功”省略文件元信息、事件数和 retryCount 断言。
- 不在 QA 阶段未经回归直接修改交付范围。
