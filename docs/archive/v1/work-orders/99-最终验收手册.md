最终结论只有：

不提供“有条件通过”。修复后必须重新验收。

## 3. 验收原则

- 使用干净 checkout/临时工作目录，不依赖开发者现有 `node_modules`、缓存或本地服务。
- 记录实际版本、时间、commit/hash；所有证据对应同一最终构建。
- 自动化、Chromium 对照和 Tabbit 实机三类证据不可互相代替。
- 不登录或提交真实考试/招聘/政务业务，不使用真实个人证件照。
- 发现缺陷先固定复现，不修改验收条件。
- 保留用户已有工作，不使用破坏性 git 命令。

## 5. G0：完整性与版本

### 5.1 检查

1. 阅读 S0–S6 handoff，状态均为 `READY_FOR_ACCEPTANCE`。
2. 检查所有 `Known limitations`、ADR 和未关闭缺陷。
3. 对比 manifest、README、测试结果的版本、commit、hash、链接。
4. 确认 PRD 和任务书未被开发阶段暗改。
5. 确认没有真实敏感照片、密钥、Token、个人路径或大体积 Base64。

### 5.2 记录命令

```powershell
git status --short
git rev-parse HEAD
git log -1 --oneline
git diff --check
Get-ChildItem -Recurse -File .\docs\handoffs
```

工作树若有未解释改动，先识别归属；不得把脏工作树直接当最终版本。

### 5.3 失败条件

- handoff/证据缺失。
- manifest 有占位 URL 或权限不可访问。
- 交付代码与测试/视频不是同一 commit/hash。
- 存在 P0/P1/P2 未关闭缺陷。

## 6. G1：干净构建

在新的临时 checkout 中：

```powershell
node --version
npm --version
npm ci
npm run check
npm run test:e2e
npm run build
(Get-Item -LiteralPath .\dist\uploadfit.js).Length
Get-FileHash -Algorithm SHA256 -LiteralPath .\dist\uploadfit.js
npm ls --omit=dev
```

核对：

- 锁文件有效，无手工安装步骤。
- build 只生成要安装的单 IIFE；无 ESM import/export 和运行时 CDN。
- 第二次 clean build hash 可复现；如构建含时间戳导致 hash 不同，必须有 ADR 且内容差异可解释，优先修为确定性。
- `dist/uploadfit.js` 记录 minified raw bytes 与 SHA-256；不设置固定体积上限。
- 不依赖 localhost、source map 或开发控制台。

任一命令非0或需要编辑代码才能继续，G1 FAIL。

## 8. G3：安全与隐私

### 8.1 静态扫描

使用 `rg` 搜索并人工审查所有命中：

```powershell
rg -n --hidden --glob '!node_modules/**' --glob '!dist/**' 'eval\s*\(|new\s+Function' .
rg -n --hidden --glob '!node_modules/**' 'innerHTML|outerHTML|insertAdjacentHTML' src
rg -n --hidden --glob '!node_modules/**' 'document\.cookie|localStorage|sessionStorage|indexedDB' src
rg -n --hidden --glob '!node_modules/**' 'fetch\s*\(|XMLHttpRequest|WebSocket|sendBeacon' src
rg -n --hidden --glob '!node_modules/**' 'https?://|<script[^>]+src=' src
rg -n --hidden --glob '!node_modules/**' 'api[_-]?key|bearer\s+|private[_-]?key|client[_-]?secret' .
rg -n --hidden --glob '!node_modules/**' '\.click\s*\(' src
```

判定：

- eval/new Function：生产源码任何命中即 FAIL。
- 动态 HTML sink：网页/AI文本进入即 FAIL；本项目优先零命中。
- 存储：只能有经过批准的匿名偏好；默认零持久化。
- 网络：普通流程零网络；Tabbit AI 仅官方 provider，输入需脱敏。
- URL：站点匹配常量可存在；运行时远程脚本/CDN 即 FAIL。
- click：只允许 UploadFit 自有 UI 交互；任何业务 DOM click 即 FAIL。

### 8.2 动态攻击/隐私测试

1. 页面相关说明注入 `<img onerror=...>`、`<script>`、HTML实体，UI只能显示文本。
2. 页面放置密码、Token、身份证号诱饵字段，ContextBundle/AI spy/日志均不得出现。
3. 网络拦截普通处理流程：图片、Base64、Blob 请求离开页面数=0。
4. AI调用检查 payload：仅相关≤2000字符文本，无 File、文件名、其他字段、Cookie、查询串。
5. 模糊错误、官方工具、规则冲突：process/injection/retry调用数=0。
6. 场景E：网页最终按钮 click=0。
7. 第二次拒收后：第三次 input/change=0。
8. 关闭后再 mutation/异步完成：无 UI更新、无注入。

### 8.3 一票否决

- 文件/像素/Base64 外传。
- 自动最终提交。
- AI 无校验直接执行。
- 静默裁剪/扁平化/放大。
- 模糊错误自动处理或无限重试。
- 绕过 isTrusted、同源、登录或权限。

任一命中直接 G3 FAIL。

## 10. G5：Tabbit 与真实 AI

### 10.1 干净安装

- 使用未装开发版本的 Tabbit profile。
- 点击真实安装链接，不复制源码。
- 记录完整 Tabbit 版本、脚本版本、安装时间。
- 打开公开测试页手动运行，复验 M02、M06、M08、M09、M15。
- 重启/刷新后的生命周期符合 README。

### 10.2 真实公开网页

1. 打开 PRD 选定的公开官方说明页；若 URL 变化，使用 ADR 记录新的稳定公开页。
2. 不登录、不触发真实报名提交。
3. 运行 UploadFit，确认只读相关规则并新增页面卡片。
4. 通过真实 Tabbit AI 调用获取候选；检查 evidence 和确定性校验。
5. 使用非敏感 fixture 在页面准备卡处理；无原 input 时只能下载/展示，不能声称已回填。

### 10.3 AI降级

- 关闭/模拟超时，明确规则测试页仍完成本地流程。
- timeout 3秒、0重试、单页最多3次。
- 无证据精确数值、未知格式、min>max 均不执行。

Mock 只能验证错误分支，不能替代真实 Tabbit AI 成功证据。DataTransfer 也必须在 Tabbit 实机而非只在 Chromium 通过。

## 11. G6：性能、体积和资源

### 11.1 性能

使用约4000×3000、≤10MB JPEG，Tabbit 同一环境至少3次：

- 总处理每次≤5秒。
- 主线程连续冻结每次≤500ms。
- 输出复检通过。
- Worker可用/禁用两种模式都有结果。

记录 P50/P95 或完整三次数据。关闭其他明显高负载应用并记录参考硬件。

### 11.2 资源

- 快速连续处理至少5次，不出现持续增长的 object URL/Worker/observer。
- 关闭后计数归零。
- detached input、导航和取消时过期任务不注入。
- 多任务队列同时处理数始终≤1。

### 11.3 体积

- `dist/uploadfit.js` 记录 minified raw bytes、SHA-256 和相邻构建差异；字节数不单独决定通过/失败。
- hash 与 manifest、安装链接实际脚本一致。
- 无 source map/远程 chunk 作为运行必需。

## 12. G7：比赛材料

在隐私窗口/干净设备核对：

- 安装链接可访问且权限正确。
- 源码/代码说明完整，`npm ci` 可复现。
- `docs/index.html` 公开、无断链、无追踪。
- 测试页 A–F 公开 HTTPS 可运行。
- 真实公开网页链接可访问。
- 视频实际时长≤180秒，使用最终构建。
- 视频覆盖真实规则理解、预检、拒收一次重试、有损确认、模糊错误不处理和不自动提交。
- 测试、安全、性能记录字段完整。
- README/说明页/视频/manifest 的承诺和限制一致。
- 无个人路径、通知、账号、密钥、真实敏感图片泄露。

占位、私有权限或 localhost 链接均视为 FAIL。
