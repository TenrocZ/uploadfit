# UploadFit 开发任务书 v1.0

本目录把 [UploadFit-PRD-v1.0.md](../UploadFit-PRD-v1.0.md) 拆成可直接交给不同 Agent 执行的工作包。每份阶段文档都包含目标、前置条件、文件边界、实现步骤、测试、退出标准和交接证据。

## 使用方式

1. 所有 Agent 先读本页、`00-项目总控与协作规则.md` 和 `01-共享契约与接口基线.md`。
2. Agent 只领取一个阶段，并在目标代码仓库 `C:\Users\蔡天乐\Desktop\黑客松\uploadfit` 内工作。
3. 阶段 Agent 只能声明“可交验”，不能自行宣布整项目完成。
4. 每个阶段完成后提交 `docs/handoffs/Sx-handoff.md`，格式见总控文档。
5. 最终是否通过，由主验收 Agent 按 `99-最终验收手册.md` 独立执行并出具结论。

## 阶段依赖

```mermaid
flowchart LR
    S0[S0 平台探针与工程骨架] --> S1[S1 DOM发现与规则引擎]
    S0 --> S2[S2 图像处理引擎]
    S1 --> S3[S3 任务编排与上传闭环]
    S2 --> S3
    S3 --> S4[S4 UI、确认与Tabbit AI]
    S4 --> S5[S5 全量测试、安全与兼容]
    S5 --> S6[S6 发布材料与演示交付]
    S6 --> A[主 Agent 最终验收]
```

S1 与 S2 可以在 S0 通过后并行。S4 的纯 UI 外壳可提前开发，但接入和验收必须等待 S3。

## 一票否决项

- Tabbit 环境无法把新文件写回 `input.files`，且没有官方替代 API，也没有明确降级方案。
- 文件、图片像素或 Base64 被发送至 UploadFit 自有服务或任意非必要第三方。
- AI 输出未经确定性校验就触发处理。
- 静默裁剪、静默透明转白底、静默低清放大。
- 对模糊错误自动处理，或同一任务自动重试超过一次。
- 自动点击保存、下一步、提交、发布、付款或删除等最终业务按钮。
- 任一 Must 用例失败、构建不可复现、安装包依赖本地开发服务器。

## 最终完成定义

代码写完不等于完成。只有 `99-最终验收手册.md` 中所有 Must 门禁均通过、比赛材料齐全，并由主验收 Agent 给出 `ACCEPTED`，项目才算完成。
