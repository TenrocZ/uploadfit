# 90 需求追踪矩阵

## 1. 使用规则

本表是最终验收索引，不是开发进度表。阶段 Agent 可以填入实现 commit 和证据路径，但只有主验收 Agent 能把 `Final` 标为 `PASS`。

状态值：

- `NOT_RUN`：尚未独立验收。
- `PASS`：代码、自动测试和必要实机证据均通过。
- `FAIL`：需求或证据不满足。
- `N/A-MVP`：PRD 明确不进入 MVP，并已验证安全提示/不误处理。

任何行没有对应证据时不得 PASS。若代码路径改变，同一提交必须更新本表。

## 7. 最终更新要求

主验收 Agent执行 [99-最终验收手册.md](99-最终验收手册.md) 时：

1. 每个 PASS 填入最终 commit/hash 对应的证据链接。
2. 任一 Must/SEC/Q硬门槛 FAIL，则最终结果不能 ACCEPTED。
3. Should 未达必须记录影响和原因；不得伪装为已实现。
4. `N/A-MVP` 项仍要验证不会误处理或破坏页面。
5. 最终报告引用本矩阵的失败行，不另造一套需求口径。
