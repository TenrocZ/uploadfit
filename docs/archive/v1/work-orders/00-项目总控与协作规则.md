# 00 项目总控与协作规则

## 1. 任务目标

在最新版 Tabbit PC 浏览器中交付一个单文件 JavaScript 脚本。它读取当前网页与图片上传相关的明确限制，在本地检查和适配 JPG/JPEG、PNG、WebP，并把通过复检的新文件放回原上传控件。它不离开当前网页、不把图片发给第三方、不替用户执行最终提交。

主 PRD 是产品和安全事实来源；本套任务书把它转换为工程执行边界。最终验收责任人是主 Agent，阶段 Agent 只负责实现、测试和提交证据。

## 2. 固定范围

### 2.1 Must

- 普通单文件 `input[type=file]` 及动态新增控件。
- JPG/JPEG、PNG、WebP。
- 格式、字节、精确/最小/最大宽高、明确比例。
- 预检、明确同页拒收兜底、最多一次重试。
- 本地转码、方向归一、缩放、压缩、必要的裁剪确认。
- DataTransfer 回填；不能回填时提供下载和明确手动步骤。
- 状态胶囊、规则/确认/成功/失败卡。
- 至少一条真实 Tabbit AI 自然语言理解路径；单次失败可本地降级。
- 稳定测试页、真实公开网页验证、测试记录、安装链接和三分钟内演示。

### 2.2 明确不做

- HEIC、PDF、Word、音视频、压缩包、多文件批量、拖拽上传。
- closed Shadow DOM、跨域 iframe、可信事件绕过、私有签名或官方审核工具仿冒。
- 人脸、服装、背景色、内容真实性等语义审核。
- 网络请求劫持、账号/云同步/历史文件库、外部 CDN 运行时依赖。
- 自动点击最终业务按钮，或把“所有上传失败”包装成可解决。

## 5. 阶段、依赖与硬闸门

| 阶段 | 依赖 | 允许并行 | 退出门禁 |

| S0 平台探针与骨架 | 无 | 否 | Tabbit 回填路径有实证；构建测试可运行 |

## 7. 模块依赖方向

允许方向：

```text
utils/config
    ↓
capabilities/dom/rules/image/injection/adapters/providers/ui
    ↓
core
    ↓
bootstrap/index
```

- `rules`、`image` 和 `injection` 不能导入 `ui` 或 `core`。
- `ui` 只渲染数据并通过回调发出用户意图，不自行做规则判断或图像处理。
- `providers/tabbit-ai.js` 是唯一允许直接调用 Tabbit AI API 的文件。
- `core/task-controller.js` 是跨模块业务编排的唯一入口。
- 所有网页外部文本必须以 `textContent` 写入 UI。

## 8. Agent开工协议

领取阶段后，Agent先完成：

1. 阅读 PRD、本总控、共享契约和本阶段文档。
2. 检查仓库状态，保留非本阶段的现有改动。
3. 确认上游 `docs/handoffs` 证据与接口均存在。
4. 运行 `npm ci`、`npm test -- --run` 和 `npm run build` 建立红/绿基线。
5. 在交接文档开头记录起始 commit、Node/npm/Tabbit 版本和已知失败。

若上游门禁未过，先提交阻塞报告，不在错误假设上继续堆实现。

## 9. 通用完成标准

每个阶段必须同时满足：

- 只实现本阶段范围，所有新增行为有测试。
- 公共函数符合共享契约，异常采用稳定错误码。
- `npm test -- --run` 与 `npm run build` 不因本阶段改动回归。
- 无密钥、Token、用户文件、Base64 或敏感网页文本进入仓库和日志。
- 无 `eval`、`new Function`、远程运行时代码。
- 新对象 URL、观察器、Worker 和事件监听器均有清理路径。
- 文档列出的 Must 退出标准全部有可复查证据。
- 新增已知限制不会突破安全红线。
- 交接文档完整，状态只能是 `READY_FOR_ACCEPTANCE` 或 `BLOCKED`。

## 11. 阻塞处理

以下情况立即停止并报告：

- 平台关键 API 与 PRD 假设不一致。
- 需要真实密钥、登录、发布权限或比赛后台操作，但当前没有授权。
- 为通过功能必须突破浏览器安全边界或产品红线。
- 上游接口缺失或互相冲突，无法通过局部兼容解决。
- 测试需要使用真实个人信息或对真实报名产生业务提交。

阻塞报告必须包含复现步骤、实际/预期、日志或截图、已经排除的原因、可选方案及推荐方案。不要留下假实现、假按钮或伪造通过记录。

## 12. 最终验收责任

阶段验收和最终验收分离：

- 阶段 Agent：证明“实现已可交验”。
- S5：证明测试覆盖、兼容性和安全基线。
- S6：证明比赛材料齐备。
- 主验收 Agent：从干净安装开始独立执行 `99-最终验收手册.md`，核对 `90-需求追踪矩阵.md`，最终只给出 `ACCEPTED` 或 `REJECTED`。

任何“人工看起来能用”都不能替代 Must 用例和证据；任何自动化绿灯也不能替代 Tabbit 实机回填、AI真实调用和不自动提交的人工验证。
