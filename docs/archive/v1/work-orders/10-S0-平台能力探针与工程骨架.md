# 10 S0：平台能力探针与工程骨架

## 1. 阶段使命

先证明 UploadFit 在真实 Tabbit 环境里能完成最关键的浏览器闭环，再建立后续 Agent 共同使用的工程骨架。本阶段不做规则识别和图像算法。

S0 结束时必须明确回答：

1. Tabbit 脚本如何安装、运行、更新、限定页面范围和结束生命周期？
2. `File`、`Blob`、`DataTransfer`、`Canvas`、`createImageBitmap`、`Worker`、`OffscreenCanvas` 是否可用？
3. 新 `File` 能否写入真实 `input.files`，网站监听器能否收到 `input/change`？
4. 合成事件受 `isTrusted=false` 限制时，产品如何降级？
5. Tabbit AI 的官方调用入口、参数、权限、超时和返回格式是什么？
6. 最终单 IIFE 脚本能否在不依赖本地服务器的情况下运行？

## 5. 实施步骤

### 5.1 初始化工程

1. 在 `C:\Users\蔡天乐\Desktop\黑客松\uploadfit` 初始化 npm 项目。
2. 添加 esbuild、Vitest、Playwright 所需开发依赖，并生成锁文件。
3. 配置 ESM 源码和 IIFE 生产输出；全局名称只用于调试，不作为业务 API。
4. 按共享契约建立目录和 npm scripts。
5. 构建时注入版本号和 `development/production` 标记；不得注入密钥。
6. 生产构建关闭敏感诊断明文，开发构建允许内存诊断。

### 5.2 防重复启动与清理骨架

- 使用稳定的全局 session key 检测同页重复运行。
- 再次运行时优先聚焦/展开现有 UI；不得重复挂 observer 和监听器。
- session 注册统一 cleanup 回调；cleanup 幂等。
- `pagehide`、明确关闭动作时清理。
- 本阶段 UI 可仅为无业务逻辑的可见状态节点，但必须能证明单例和移除。

### 5.3 能力检测

`detectCapabilities()` 至少返回：

```js
{
  file: true,
  blob: true,
  dataTransfer: true,
  inputFilesAssignable: true,
  canvasToBlob: true,
  createImageBitmap: true,
  worker: true,
  offscreenCanvas: true,
  blobWorkerAllowed: true,
  tabbitAi: {
    available: false,
    officialApi: null,
    notes: ""
  }
}
```

能力探针不得污染业务表单。测试 `input.files` 赋值时使用独立、不可见但可清理的临时 input；结束后移除。

### 5.4 最小回填闭环

实现共享契约的 `injectFile(input, file, options)`：

1. 验证 input 仍连接在 DOM、类型为 file、file 是 `File`。
2. 获取该 input 的 guard；设置一次性注入令牌。
3. 创建 `DataTransfer`，添加新 File，赋值 `input.files`。
4. 立即验证长度、对象名称/类型/大小与目标一致。
5. 按顺序分发 bubbles+composed 的 `input`、`change`。
6. 监听器只消费一次令牌；不能按文件名防递归。
7. 返回 `InjectionResult`，不吞掉失败。

`options` 至少支持：

```js
{
  dispatchEvents: true,
  reason: "processed" | "restore" | "probe"
}
```

不要把 `preventDefault()` 当作取消文件选择的可靠依据，也不要试图伪造 `isTrusted`。

### 5.5 恢复和降级

- `restoreOriginal(task)` 复用 `injectFile`，不复制另一套实现。
- DataTransfer 不可用或赋值失败：返回 `DATATRANSFER_UNAVAILABLE` 或 `INJECTION_FAILED`。
- 文件已写入但网站不响应合成事件：返回/记录 `UNTRUSTED_EVENT_BLOCKED`，建议用户点网页原按钮。
- 文件无法写入：后续产品必须能提供下载；S0 只建立结果枚举和探针说明，不必做正式下载 UI。
- 任何失败不能修改其他表单值或替换原 input 节点。

### 5.6 探针页面

`probe.html` 必须包含：

- 普通单文件图片 input。
- 原生捕获、目标/冒泡监听器，记录事件类型、顺序、`isTrusted`、文件元信息。
- 页面显示当前 `input.files[0]` 的 MIME、字节和名称；仅使用非敏感生成文件。
- “生成并回填 B 文件”“恢复 A 文件”“清空日志”按钮。
- 重复注入计数器，能肉眼发现递归。

测试数据在浏览器内生成，不提交真实照片。

### 5.7 Tabbit AI 探针

- 只使用官方示例确认 API，不根据名字猜测 `window.tabbit` 等全局。
- 发送无敏感信息的固定测试句：“JPG格式，30KB到120KB，390×567像素”。
- 记录调用代码所在环境、是否需要权限声明、超时、实际返回形态和错误形态。
- 若可用，仅把最小适配说明写入能力文档；正式 provider 留给 S4。
- 若不可用，记录官方资料/支持渠道反馈和日期，状态标为阻塞，不加“模拟 AI 成功”。

## 8. 阶段退出标准

### PASS

- 所有 S0-T 自动测试通过。
- `npm ci` 后可在干净目录构建。
- Tabbit 实机证明 `input.files` 写入成功；合成事件至少能被探针页面读取。
- `isTrusted=false` 边界有准确记录。
- 官方 AI 调用方式已确认，或有明确外部阻塞证据且核心本地路径不受影响。
- 交接文档和证据齐全。

### BLOCKED_CORE_GATE

若真实 Tabbit 无法赋值 `input.files` 且无官方替代 API：

1. 不进入 S1/S2 的正式产品开发。
2. 提交最小复现、浏览器对照、Tabbit 版本和错误。
3. 给出“页面内处理后下载，再由用户重选”的降级产品方案。
4. 等主 Agent和赛道技术支持决定是否调整产品形态。

## 9. 禁止事项

- 不实现规则解析、Canvas 算法或正式 UI。
- 不替换页面原 input 来抢事件。
- 不 monkey patch `fetch`/`XMLHttpRequest`。
- 不硬编码未验证的 Tabbit AI 全局方法。
- 不把 Playwright/Chrome 成功当成 Tabbit 实机成功。
- 不把“input 中已有文件”夸大为“网站已经上传成功”。
