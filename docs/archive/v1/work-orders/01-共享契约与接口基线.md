# 01 共享契约与接口基线

## 1. 目的

本文件冻结跨阶段接口，保证多个 Agent 可以独立开发后集成。以下结构是最低兼容契约：可以增加可选字段，但不得改名、改变含义、降低安全条件或让调用方依赖未记录的副作用。

所有对象使用普通 JavaScript 和 JSDoc；边界输入必须运行时校验。禁止改成 TypeScript。

## 3. 构建与脚本契约

`package.json` 至少提供：

| 命令 | 含义 |
|---|---|
| `npm run build` | 生产构建，单个 minified IIFE 到 `dist/uploadfit.js` |
| `npm run build:dev` | 可诊断开发构建，不作为提交物 |
| `npm test -- --run` | 一次性运行全部 Vitest 单元/集成测试 |
| `npm run test:e2e` | 无头浏览器 E2E |
| `npm run serve:test` | 启动本地测试页并打印地址 |
| `npm run check` | 顺序执行单测、构建和静态检查；不能启动常驻服务 |

最终 `dist/uploadfit.js`：

- 不含 ESM `import/export`。
- 可在页面上下文直接执行。
- 重复运行不产生第二套监听器或 UI。
- minified 文件记录 raw bytes、SHA-256 和相邻构建差异；不设置固定体积上限，体积不作为验收阻断项。
- 不需要 source map、开发服务器或运行时网络依赖。

## 4. 配置常量

集中在 `src/config.js`，测试可以注入覆盖值，业务模块不得散落魔法数字。

| 常量 | 基线 |
|---|---:|
| `CONTEXT_TEXT_LIMIT` | 6000 字符/上传器 |
| `AI_TEXT_LIMIT` | 2000 字符/调用 |
| `AI_TIMEOUT_MS` | 3000 |
| `AI_CALL_LIMIT_PER_PAGE` | 3 |
| `REJECTION_WINDOW_MS` | 30000 |
| `DOM_DEBOUNCE_MS` | 100 |
| `AUTO_RULE_CONFIDENCE` | 0.90 |
| `CONFIRM_RULE_CONFIDENCE` | 0.75 |
| `ASPECT_RATIO_TOLERANCE` | 0.015 |
| `MAX_AUTO_RETRIES` | 1 |
| `MAX_INPUT_BYTES` | 50 × 1024 × 1024 |
| `MAX_DECODE_PIXELS` | 80,000,000 |
| `MAX_DIMENSION` | 20,000 |
| `ENCODE_QUALITY_MIN/MAX` | 0.45 / 0.95 |
| `ENCODE_SEARCH_STEPS` | 8 |
| `RESIZE_RETRY_LIMIT` | 3 |
| `TARGET_MAX_RATIO` | 0.90 |

大小解析规则：

- 页面最大 100KB → 100,000 bytes；最大 1MB → 1,000,000 bytes。
- 页面最小 30KB → 30,720 bytes；最小 1MB → 1,048,576 bytes。
- 页面给出精确字节数时不换算。
- 输出最大目标再乘 0.90；UI保留原网页单位。

## 5. 稳定枚举

### 5.1 会话/任务状态

`BOOTING`、`SCANNING`、`ARMED`、`INSPECTING`、`PASSTHROUGH`、`WAITING_REJECTION`、`NEEDS_CONFIRMATION`、`PROCESSING`、`INJECTING`、`RETRYING`、`SUCCESS`、`STOPPED`、`DISPOSED`。

### 5.2 规则来源

`adapter`、`rejection`、`html-attribute`、`nearby-text`、`selected-text`、`ai`、`weak-page-text`。

其优先级必须依次为 700、600、500、400、300、200、100；同优先级冲突不得靠数组顺序暗中裁决。

### 5.3 处理操作

`ORIENT`、`CONVERT`、`RESIZE`、`CROP`、`FLATTEN_BACKGROUND`、`UPSCALE`、`ENCODE`、`COMPRESS`。

`CROP`、`FLATTEN_BACKGROUND`、`UPSCALE` 必须产生用户确认项，确认前 `ProcessingPlan.executable=false`。

### 5.4 任务来源与确认类型

任务来源只允许 `preflight`、`rejection`、`manual-card`。`manual-card` 用于真实说明页没有原上传框、由 UploadFit 卡片让用户本地选择 fixture 的准备模式；它不能声称完成网页回填。

确认类型只允许 `RULE_CONFIDENCE`、`CROP`、`FLATTEN_BACKGROUND`、`UPSCALE`。每项结构：

```js
{
  id: "confirmation-random-id",
  type: "CROP",
  required: true,
  resolved: false,
  accepted: null,
  payload: null
}
```

用户接受后由 controller 创建更新后的不可变计划；只要存在未解决或被拒绝的 required confirmation，计划就不能执行。`RULE_CONFIDENCE` 与三类有损确认分别记录，不得一次笼统同意。

## 6. 核心数据结构

### 6.1 UploaderContext

```js
/**
 * @typedef {Object} UploaderContext
 * @property {HTMLInputElement} input
 * @property {string} uploaderId
 * @property {string} label
 * @property {string[]} nearbyTexts
 * @property {string[]} alertTexts
 * @property {string|null} accept
 * @property {boolean} multiple
 * @property {string} pageUrl
 * @property {string} pageTitle
 * @property {Object|null} adapter
 */
```

`pageUrl` 仅供当前页面适配器匹配；发送给 AI 前必须移除查询串和 hash，默认完全不发送 URL。

### 6.2 ContextBundle

```js
const ContextBundle = {
  uploaderId: "uploader-random-id",
  label: "证件照",
  attributes: {
    accept: "image/*",
    multiple: false,
    required: true
  },
  selectedText: null,
  nearbyTexts: [],
  alertTexts: [],
  normalizedText: "",
  truncated: false
};
```

`normalizedText` 最多 6000 字符。不得包含密码、验证码、其他表单值、DOM序列化或脚本/样式内容。

### 6.3 RuleCandidate

```js
const RuleCandidate = {
  sourceType: "nearby-text",
  sourcePriority: 400,
  evidence: ["JPG格式，30KB—120KB，390×567像素"],
  confidence: 0.96,
  rules: {
    formats: ["image/jpeg"],
    extensions: ["jpg", "jpeg"],
    minBytes: 30720,
    maxBytes: 120000,
    width: { exact: 390, min: null, max: null },
    height: { exact: 567, min: null, max: null },
    aspectRatio: { value: 390 / 567, tolerance: 0.015 },
    count: { max: 1 },
    semanticRequirements: []
  },
  advisoryOnly: false
};
```

数字必须有限、为正且在配置防护范围内；`evidence` 必须来自本次允许读取的文本。

### 6.4 RuleSet

```js
const RuleSet = {
  formats: ["image/jpeg"],
  extensions: ["jpg", "jpeg"],
  minBytes: 30720,
  maxBytes: 120000,
  width: { exact: 390, min: null, max: null },
  height: { exact: 567, min: null, max: null },
  aspectRatio: { value: 390 / 567, tolerance: 0.015 },
  dpi: 300,
  count: { max: 1 },
  background: "blue",
  semanticRequirements: ["不得拉伸"],
  confidence: 0.96,
  sources: [],
  conflicts: [],
  actionable: true
};
```

`dpi`、背景色、近期、免冠、清晰、官方工具等只展示，不参与自动执行。存在不可解冲突时 `actionable=false`。

### 6.5 ImageMetadata

```js
const ImageMetadata = {
  localName: "only-used-locally.jpg",
  mime: "image/jpeg",
  extension: "jpg",
  size: 500000,
  width: 390,
  height: 567,
  aspectRatio: 390 / 567,
  orientation: 1,
  hasAlpha: false,
  decodable: true
};
```

`localName` 不得进入 AI、日志、诊断或测试结果；测试结果只记 MIME、字节和宽高。

### 6.6 ValidationResult

```js
const ValidationResult = {
  valid: false,
  violations: [
    { code: "FILE_TOO_LARGE", expected: 120000, actual: 500000 }
  ],
  warnings: [],
  safeAutoFixes: ["COMPRESS"],
  requiredConfirmations: [],
  unfixable: []
};
```

`valid=true` 时不得重新编码、改名或重新注入。

### 6.7 ProcessingPlan

```js
const ProcessingPlan = {
  targetMime: "image/jpeg",
  targetWidth: 390,
  targetHeight: 567,
  crop: null,
  flattenBackground: null,
  qualityRange: [0.45, 0.95],
  targetMinBytes: 30720,
  targetMaxBytes: 108000,
  operations: ["ORIENT", "RESIZE", "ENCODE", "COMPRESS"],
  confirmations: [],
  warnings: [],
  executable: true
};
```

确认项未决、规则冲突、官方工具要求或算法证明无法同时满足规则时，`executable=false`。

### 6.8 ProcessResult

```js
const ProcessResult = {
  file: null,
  metadata: {
    mime: "image/jpeg",
    size: 88123,
    width: 390,
    height: 567
  },
  operations: [],
  validation: { valid: true, violations: [] },
  durationMs: 842,
  warnings: []
};
```

只有 `file instanceof File`、`validation.valid=true` 且文件可再次解码时才允许进入注入。

### 6.9 UploadTask

```js
const UploadTask = {
  taskId: "crypto-random-id",
  inputElement: null,
  uploaderId: "",
  originalFile: null,
  processedFile: null,
  rules: null,
  source: "preflight",
  status: "INSPECTING",
  retryCount: 0,
  createdAt: 0,
  objectUrls: [],
  warnings: [],
  result: null,
  abortController: null
};
```

`taskId` 必须随机生成；禁止以文件名、DOM id 或时间戳单独作为标识。每个 input 有独立上下文，同时最多一个任务处于 `PROCESSING`。

### 6.10 InjectionResult

```js
const InjectionResult = {
  ok: true,
  inputFilesVerified: true,
  eventsDispatched: ["input", "change"],
  fallback: null,
  errorCode: null
};
```

`fallback` 仅允许 `manual-submit` 或 `download`。不得声称合成事件是可信事件。

## 7. 公共函数

必须保留下列导出名和必需参数；可增加末尾可选 options。

```js
discoverUploaders(root = document)
extractRelevantContext(input, selectedText)
parseRulesDeterministically(context)
extractRulesWithAI(context)
resolveRules(candidates)
inspectImage(file)
validateFile(metadata, rules)
createProcessingPlan(metadata, rules)
resolveProcessingConfirmation(plan, confirmation)
processImage(file, plan, progressCallback)
injectFile(input, file, options)
restoreOriginal(task)
observeRejection(task, uploaderContext)
cleanupSession()
```

异步函数：

- `extractRulesWithAI`、`inspectImage`、`processImage` 返回 Promise。
- `resolveProcessingConfirmation` 是纯函数，校验 confirmation id/type/payload 后返回新计划，不原地修改旧计划。
- `observeRejection` 返回幂等停止函数；重复调用不得抛错。
- `cleanupSession` 必须幂等。
- `injectFile` 在同步 DataTransfer 路径返回 `InjectionResult`；若平台官方 API 是异步，只能通过 ADR 改为 Promise，并同步更新全部调用方和测试。

## 8. Provider 与适配器

### 8.1 AI Provider

```js
class RuleUnderstandingProvider {
  async isAvailable() {}
  async extractRules({ text, locale, pageType }) {}
}
```

只有 `src/providers/tabbit-ai.js` 可接触平台 API。Provider 返回候选，不得调用 controller、image 或 injection 模块。

### 8.2 SiteAdapter

```js
const SiteAdapter = {
  id: "example-site",
  matches(url) {},
  discoverUploaders(document) {},
  extractContext(input) {},
  findErrorNodes(input) {},
  isAutoUpload(input) {},
  beforeInjection(task) {},
  afterInjection(task) {}
};
```

钩子不得点击最终按钮、修改其他表单字段、绕过权限或读取请求体。MVP 至多一个真实站点适配器。

## 9. 状态转移约束

主路径：

```text
BOOTING → SCANNING → ARMED
ARMED → INSPECTING
INSPECTING → PASSTHROUGH → ARMED
INSPECTING → WAITING_REJECTION
INSPECTING → NEEDS_CONFIRMATION → PROCESSING
INSPECTING → PROCESSING
PROCESSING → INJECTING
INJECTING → RETRYING | SUCCESS
RETRYING → SUCCESS | STOPPED
任意活跃状态 → STOPPED | DISPOSED
```

约束：

- `PASSTHROUGH` 不阻断原事件。
- 规则不足进入 `WAITING_REJECTION`，不得先改文件。
- 用户取消确认进入 `STOPPED`，原文件不变。
- 注入前必须完成最终复检。
- `retryCount` 在重新分发事件前原子增加，最大为 1。
- `DISPOSED` 后不得再更新 UI、响应 DOM 或继续异步处理。

## 10. 稳定错误码

规则/文件：

`FORMAT_NOT_ALLOWED`、`FILE_TOO_LARGE`、`FILE_TOO_SMALL`、`WIDTH_TOO_SMALL`、`WIDTH_TOO_LARGE`、`HEIGHT_TOO_SMALL`、`HEIGHT_TOO_LARGE`、`DIMENSION_MISMATCH`、`ASPECT_RATIO_MISMATCH`、`ORIENTATION_MISMATCH`、`TRANSPARENCY_WILL_BE_LOST`、`DECODE_FAILED`、`UNSUPPORTED_FORMAT`、`AMBIGUOUS_RULES`、`OFFICIAL_TOOL_REQUIRED`。

平台/运行时：

`FILE_TOO_LARGE_TO_PROCESS`、`PIXEL_LIMIT_EXCEEDED`、`CANVAS_LIMIT_EXCEEDED`、`PROCESSING_FAILED`、`OUTPUT_VALIDATION_FAILED`、`USER_CONFIRMATION_REQUIRED`、`DATATRANSFER_UNAVAILABLE`、`INJECTION_FAILED`、`UNTRUSTED_EVENT_BLOCKED`、`INPUT_DETACHED`、`AMBIGUOUS_REJECTION_ASSOCIATION`、`AI_UNAVAILABLE`、`AI_TIMEOUT`、`AI_INVALID_OUTPUT`、`RULE_CONFLICT`、`USER_CANCELLED`、`SESSION_DISPOSED`。

用户文案可以本地化，但代码、日志、测试和交接证据使用稳定英文错误码。

## 11. 诊断事件

固定事件名：

`SESSION_STARTED`、`CAPABILITY_DETECTED`、`UPLOADER_DISCOVERED`、`CONTEXT_EXTRACTED`、`RULES_PARSED_LOCAL`、`RULES_PARSED_AI`、`RULE_CONFLICT`、`FILE_SELECTED`、`FILE_VALID`、`FILE_INVALID`、`REJECTION_DETECTED`、`PROCESS_STARTED`、`CONFIRMATION_REQUIRED`、`PROCESS_COMPLETED`、`INJECTION_COMPLETED`、`RETRY_TRIGGERED`、`TASK_SUCCEEDED`、`TASK_STOPPED`、`SESSION_DISPOSED`。

允许字段：时间、事件名、taskId、MIME、字节、宽高、结构化规则、耗时、错误码。禁止字段：完整文件名、图片内容/Base64、姓名/证件号、Cookie/Token、完整页面文本和 URL 查询参数。

## 12. 安全不变量

- 文件二进制和像素只存在于当前页面/Worker 内存。
- AI 输入最多 2000 字符，先脱敏，只包含相关文本。
- AI evidence 必须能在输入中找到或近似匹配；精确数值不能无证据产生。
- 高优先级规则冲突时低优先级不得覆盖；不可解冲突不执行。
- 不 monkey patch `fetch`/`XMLHttpRequest`，不读取上传请求或响应。
- 不用 `innerHTML` 拼网页或 AI 文本；不用 `eval`/`new Function`。
- 每个 object URL、Worker、Observer、监听器和异步任务都有可追踪清理。
- 有损处理确认和最终提交边界不可通过配置关闭。

## 13. 公共接口变更流程

确需变更时：

1. 新增 ADR。
2. 在本文件先更新契约和版本说明。
3. 同一变更中更新所有实现、调用方、测试、任务书引用和追踪矩阵。
4. 提供向后兼容或明确迁移步骤。
5. 未经主 Agent确认不得合并会改变安全语义或最终验收口径的变更。

阶段 Agent 不得通过复制结构、局部别名或隐式类型转换绕开契约。
