## 验收中发现并修复

1. 完整 M4A 的末级 box 声明越过 EOF 时曾被当作“允许的头部前缀”接受。现仅在明确的有界头部探测模式容忍不完整顶层 box；完整文件中的截断 box 稳定拒绝，并新增签名回归。
2. 原 P02 用 `free` box 把约 17KB AAC 扩到 30MiB，不能证明大音频处理；同时 production 对每个 AAC sample 单独 `File.slice()`，真实长 M4A 会产生大量异步读取。现测试生成 AAC payload 本身不少于 30MiB，production 按不超过 4MiB 的连续 sample batch 读取，再逐 access unit 解码。
3. 真实 30MiB M4A 会超过旧的 120 秒通用运行时默认值。音频 Worker 生产处理上限调整为 15 分钟；用户取消门禁仍为 1 秒，不扩大取消等待。
4. VocaText 的 `File exceeds 25 MB limit.` 已被监听，但 rejection candidate 的空 `formats/extensions` 曾覆盖上传框 accept 规则，造成 `REJECTION_RULE_NOT_STRICTER`。resolver 现把空数组视为“该来源未提供此字段”，保留低优先级的实际格式证据，并补 unit + cross-module integration 回归。

## 最终裁决

S4.1 工单的 MP3→MP3 重编码、AAC-LC M4A→MP3、英文大小/时长规则、瞬态拒收监听、最多一次重试、Worker 资源上界、取消/复用、最终验证和公开站点正例均已闭环。未发现仍阻断 S5/发布收尾的 S4.1 缺陷。

支持范围仍按 ADR-006 冻结：不支持 HE-AAC/HE-AACv2、ALAC、DRM/加密、fragmented MP4、raw ADTS AAC、损坏/越界表及三声道以上；这些输入应稳定停止，不属于本轮遗留缺陷。
